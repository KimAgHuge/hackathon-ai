## 1. 이번 작업의 결론

실제 연결 기준으로 다음 항목까지 완료했다.

```text
Supabase 로그인/JWT
  -> 조직 조회와 선택
  -> 실제 프로젝트 생성
  -> private GitHub 저장소 연결
  -> Supabase PostgreSQL 읽기 계정 연결
  -> analysis_jobs PENDING 생성
```

Mac Studio의 AI 실행 경로도 별도로 실제 검증했다.

```text
FastAPI :8000
  -> Ollama :11434
  -> devstral:latest
  -> 한국어 구조화 JSON 응답
```

두 흐름은 각각 동작하지만, `analysis_jobs.PENDING` 작업을 가져와 Git/DB 정보를
수집하고 FastAPI에 전달하는 Worker는 아직 없다. 따라서 제품 화면에서 실제
전체 영향도 분석은 아직 실행되지 않는다.

## 2. Git 기준 상태

이번 작업을 시작한 기준은 다음과 같다.

```text
branch: main
base HEAD: 1d8a8df
base origin/main: 1d8a8df
```

`1d8a8df` 이후 이번 인수인계 commit에는 다음 변경이 포함된다.

- PostgreSQL 동적 연결의 TLS/read-only 강제와 서버 상태 검증
- DB 연결 서비스 단위 테스트
- 프로젝트 등록 화면의 조직 조회·선택·생성
- 프로젝트 생성/수정 payload의 `organizationId`
- Mock 조직 권한과 조직 API
- 이 인수인계 문서

다음 PC에서는 아래 명령으로 실제 시작 commit을 확인한다.

```bash
git pull origin main
git status -sb
git log -5 --oneline
```

이 문서를 포함한 최신 commit에서 작업해야 한다.

## 3. 이번에 완료한 소스 변경

### 3.1 프로젝트 조직 연결

실제 API 모드에서 Backend의 `ProjectCreateRequest.organizationId`는 필수지만,
기존 Frontend는 이 값을 보내지 않았다. Mock 모드에서는 Backend 호출을 하지 않아
문제가 드러나지 않았다.

수정 내용:

- `GET /api/organizations`로 로그인 사용자의 활성 조직 조회
- 활성 조직이 하나면 자동 선택
- 여러 조직이면 프로젝트 등록 화면에서 선택
- 조직이 없고 `ORGANIZATION_MANAGE` 권한이 있으면 화면에서 새 조직 생성
- 프로젝트 생성 및 수정 payload에 `organizationId` 포함
- 조직이 선택되지 않으면 Git 연결과 프로젝트 저장 버튼 비활성화
- Mock 모드에도 동일한 조직 계약 반영

주요 파일:

```text
frontend/src/api/organizationApi.js
frontend/src/api/projectApi.js
frontend/src/components/project/connection/ProjectConnectionStep.vue
frontend/src/components/project/connection/ProjectSourceForm.vue
frontend/src/stores/authStore.js
frontend/src/views/ProjectRegisterView.vue
```

실제 화면에서 `테스트 조직 (OWNER)`을 선택한 프로젝트 생성과 Git 연결 성공을
확인했다.

### 3.2 PostgreSQL 읽기 전용 연결 강화

Supabase Shared Pooler에서 읽기 전용 계정 로그인을 직접 확인했다. Pooler 연결에서
role 기본 설정만으로는 `transaction_read_only=on`을 보장할 수 없으므로, Backend가
매 연결마다 읽기 전용 상태를 강제하고 실제 서버 상태를 검증하도록 변경했다.

PostgreSQL JDBC 연결 속성:

```text
sslmode=require
readOnly=true
readOnlyMode=always
currentSchema=<사용자가 선택한 schema>
logServerErrorDetail=false
```

연결 후 다음 값을 확인한다.

```sql
select current_setting('transaction_read_only');
```

결과가 `on`이 아니면 연결 테스트를 실패 처리한다. 읽기 전용 설정 API 자체가
실패해도 더 이상 예외를 무시하지 않는다.

주요 파일:

```text
backend/src/main/java/com/doenaai/project/connection/service/DatabaseConnectionService.java
backend/src/test/java/com/doenaai/project/connection/service/DatabaseConnectionServiceTest.java
```

실제 Supabase 입력값 형식:

```text
DB 종류: PostgreSQL
호스트: Supabase Shared Pooler host
포트: 5432
데이터베이스: postgres
스키마: public
계정: <reader_role>.<project_ref>
비밀번호: 별도 보안 채널에서 관리
```

실제 화면 검증 결과:

```text
연결 상태: 성공
DB 제품: PostgreSQL
DB 버전: 17.6
```

연결 테스트는 실제 업무 행을 조회하지 않는다. 현재 확인하는 범위는 로그인,
읽기 전용 세션, 연결 유효성, DB 제품명과 버전이다.

### 3.3 Git 실제 연결

프로젝트 등록 화면에서 다음 실제 흐름을 확인했다.

```text
조직 선택
  -> 프로젝트 생성
  -> GitHub HTTPS username + token 인증
  -> main branch 확인
  -> commit SHA 확인
  -> 저장소 연결 성공
```

토큰은 문서나 로그에 기록하지 않는다. Frontend는 토큰을 Pinia 또는 브라우저
저장소에 보존하지 않으며 Backend 저장 시 암호화한다.

## 4. AI 분석/추론 서버 실제 검증 결과

실행 상태:

```text
FastAPI: http://127.0.0.1:8000
Ollama:  http://127.0.0.1:11434
모델:    devstral:latest
```

다음 항목을 실제 확인했다.

- `GET /health` HTTP 200
- Ollama 설치 모델 목록에서 `devstral:latest`, `qwen3.8:27b` 확인
- FastAPI의 `POST /api/analysis/project` 실제 호출
- Devstral이 Ollama 메모리에 올라온 상태 확인
- 모델 실행 중 약 36GB 메모리 사용 확인
- 약 50초 후 HTTP 200
- 한국어 summary, framework, risk, evidence, recommendation JSON 반환
- 비밀번호, token, private key는 AI 요청에 포함하지 않음

이 검증은 Worker를 거치지 않고 FastAPI에 구조화된 프로젝트 요약을 직접 보낸
단독 통합 테스트다. 따라서 생성된 `analysis_jobs` 행의 상태는 변경하지 않는다.

## 5. 현재 분석 화면의 정확한 상태

Frontend에서 `분석 시작`을 누르면 다음은 실제로 수행된다.

```text
Git 연결정보 저장
DB 연결정보 암호화 저장
Git 원격 branch 재검증
analysis_jobs에 PROJECT_SCAN/PENDING 생성
분석 진행 화면으로 이동
```

현재 수행되지 않는 작업:

```text
PENDING 작업 선점
검증 commit checkout
소스코드 상세 분석
읽기 계정 DB metadata 수집
소스 SQL/JPA/MyBatis와 DB 객체 연결
요구사항/변경 요청과 구조 정보 결합
Spring Boot -> FastAPI 호출
analysis_results 저장
RUNNING/COMPLETED/FAILED 상태 변경
Frontend polling과 실제 로그 표시
```

따라서 현재 진행 화면의 다음 정보는 실제 분석 결과가 아니다.

- Controller/Service/Mapper/Vue 개수
- DB 테이블/컬럼/인덱스/관계 개수
- 실시간 분석 로그 문구
- 기존 통합 구조와 영향도 화면 데이터

현재 화면은 작업 상태를 한 번 조회하며 `PENDING 0%`에서 멈춘다. 화면에 명시된
것처럼 일부 로그와 결과는 하드코딩 또는 Mock이다.

## 8. 다음 작업: 최소 분석 Worker

다음 작업자는 아래 순서로 최소 수직 흐름을 먼저 구현한다.

```text
1. analysis_jobs PENDING 한 건을 원자적으로 선점
2. status=RUNNING, started_at과 단계별 progress 갱신
3. 저장된 Git 인증정보를 복호화해 snapshot commit checkout
4. manifest와 소스 파일을 정적 분석
5. 저장된 DB 비밀번호를 복호화해 read-only JDBC 연결
6. DatabaseMetaData로 table/column/PK/FK/index만 수집
7. 소스의 SQL/JPA/MyBatis 참조와 DB 객체 연결
8. 비밀정보를 제거한 sourceSummary/databaseSummary/relations 생성
9. 내부 API key로 FastAPI POST /api/analysis/project 호출
10. analysis_results.original_result에 JSON 저장
11. status=COMPLETED와 progress=100 갱신
12. 예외 발생 시 비밀정보 없는 error_message와 FAILED 저장
13. Frontend에서 2~3초 polling 후 실제 결과 표시
```

해커톤 최소 구현에서는 기존 `analysis_jobs`와 `analysis_results`를 사용할 수 있다.
다중 Worker, lease, heartbeat, retry와 고착 작업 복구가 필요해질 때만 신규 migration을
추가한다. 기존 `001`~`007` migration은 수정하지 않는다.

### DB 수집 안전 원칙

- 업무 table의 행 데이터는 조회하지 않는다.
- JDBC `DatabaseMetaData`와 `information_schema` 수준만 사용한다.
- PostgreSQL 세션의 `transaction_read_only=on`을 다시 검증한다.
- AI 분석/추론 서버에는 host, username, password, token, ciphertext를 전달하지 않는다.
- table/column/index/FK 이름과 코드상의 참조 근거만 전달한다.

### Git 수집 안전 원칙

- 원격 저장소의 script를 실행하지 않는다.
- `npm install`, Gradle build, Maven build, `setup.py`를 실행하지 않는다.
- 검증된 commit SHA와 실제 checkout SHA가 다르면 실패 처리한다.
- `.env`, private key, token 파일과 credential 값을 AI 입력에서 제외한다.
- 임시 checkout 디렉터리는 성공과 실패 모두에서 삭제한다.

## 9. 변경 영향도 분석 입력

프로젝트 전체 scan만으로는 구조와 일반 위험을 설명할 수 있지만, 특정 변경의
영향도는 판단할 수 없다. 실제 영향도 분석에는 다음과 같은 변경 요청이 필요하다.

```text
예: users.email 컬럼명을 변경하면 어느 Vue 화면, API, Service와 SQL이 영향을 받는가?
```

이미 `analysis_jobs.requirement_version_id`가 있으므로 Worker는 값이 있을 때 해당
요구사항 버전의 제목, 정제 내용과 인수 조건을 AI 입력에 포함해야 한다. 값이 없는
`PROJECT_SCAN`은 전체 구조 snapshot 생성 용도로 취급한다.

## 10. 보안 및 commit 금지 항목

다음 실제 값은 문서, commit, 콘솔 로그와 AI prompt에 남기지 않는다.

- Supabase DB password
- Supabase secret/service role key
- GitHub access token
- DB 읽기 계정 password
- `DOENAAI_AI_INTERNAL_API_KEY`
- `DOENAAI_CREDENTIAL_ENCRYPTION_KEY`
- SSH private key와 passphrase

특히 다음 파일은 실제 값이 들어갈 수 있으므로 commit 전 항상 확인한다.

