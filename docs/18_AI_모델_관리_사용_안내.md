# AI 모델 관리 사용 안내

## 이 화면의 역할

왼쪽의 **AI 모델 관리**에서 현재 AI 분석/추론 서버의 모델 상태와 등록한 모델 버전, 평가 기록을 확인한다.
관리 정보 저장, 설치 모델 전환, AI 학습 서버의 작업 실행을 구분한다.
화면은 실제 백엔드 API를 사용하며, 연결 실패를 예시 데이터나 임의 정확도로 바꾸지 않는다.

## 설치된 Ollama 모델 선택과 복구

**AI 서버에 설치된 모델**에서 연결된 AI 분석/추론 서버의 Ollama 목록을 불러온다.
브라우저가 실행되는 PC의 모든 AI 프로그램을 탐색하는 기능은 아니다.
설치된 문장 생성 모델만 대상으로 하며 임베딩 전용 모델과 클라우드 실행 모델은 제외한다.

1. **설치 목록 새로고침** 후 전환할 모델을 선택한다.
2. **JSON 응답 검증**으로 짧은 한국어 고정 응답을 확인한다. 모델을 실제 실행하므로 자원을 사용한다.
3. 시험 결과가 유효한 동안 영향 안내를 확인하고 **모델 전환**을 실행한다.
4. 필요하면 **이전 모델로 복구**에서 직전 선택으로 한 번 되돌린다.

검증은 기본 5분 동안만 유효하며 모델 파일 식별값과 선택 설정 버전에 연결된다.
시험 뒤 설치 파일이나 설정이 바뀌면 다시 확인해야 한다. 짧은 JSON 시험은 긴 입력 처리나 업무 정확도를 보장하지 않는다.
전환은 새 분석부터 적용한다. 이미 실행 중인 분석은 모든 단계에서 시작 당시의 모델을 유지한다.
설정은 AI 서버의 `.runtime/model-selection.sqlite3`에 보존되며, 재시작해도 선택한 모델을 유지한다.
`DOENAAI_AI_MODEL`은 최초 기본값이며 저장된 선택값을 덮어쓰지 않는다. 기본 Qwen 설정은 이번에 변경하지 않았다.
이 상태 파일과 학습 산출물은 Git에 포함하지 않는다. AI 서버를 여러 프로세스로 실행할 때는 같은 상태 파일을 사용한다.

등록한 LoRA 파일이 이 목록에 자동으로 추가되지는 않는다. 호환되는 기반 모델과의 변환·병합·Ollama 등록은 별도 작업이다.
NAS 패키지의 서명 확인도 운영 품질 승인이나 자동 설치를 의미하지 않는다.

## 현재 사용 모델 확인

백엔드가 설정된 AI 분석/추론 서버의 `/api/models/health`를 내부 인증으로 조회한다.
사용 가능 표시는 설정 모델의 설치 여부와 서버 응답을 확인했다는 뜻이다.
모델이 지금 메모리에 올라왔는지, 추론이 성공했는지, 학습 품질이 좋아졌는지까지 확인한 것은 아니다.
DB의 배포 기록만으로 실제 사용 모델을 추정하지 않는다.
서버 주소와 내부 키는 백엔드 로컬 설정을 사용하며 브라우저에 제공하지 않는다.

## 모델 버전 등록

학습 서버에서 산출물과 기반 모델 정보를 확인한 뒤 **모델 버전 등록**을 사용한다.

- 처음 등록하는 모델이면 새 모델 이름을 입력한다. 같은 모델의 다음 버전이면 기존 모델을 선택한다.
- 기반 모델 식별자는 실제 학습 기록과 맞춘다. 버전은 같은 모델 안에서 중복되지 않게 지정한다.
- 파일 유형은 기반 모델, LoRA 어댑터, 병합 모델, 외부 모델 중 실제 산출물에 맞춰 선택한다.
- 파일 위치는 공유 NAS 폴더 기준의 상대경로로 입력한다. 비밀번호, 인증 토큰, 전체 접속 주소는 입력하지 않는다.
- SHA-256은 실제로 확인한 값이 있을 때만 입력한다. 임의 값으로 채우지 않는다.
- 학습 데이터셋 이름과 메모는 출처와 확인한 범위를 설명하는 기록이다. 데이터셋 파일을 함께 보내지는 않는다.

등록은 DB의 관리 정보만 저장한다. 파일 복사, 해시 대조, 학습, 자동 평가 또는 운영 모델 전환은 실행하지 않는다.
`READY`도 등록 상태이며 파일이나 배포 검증 완료를 뜻하지 않는다.
새 모델과 첫 버전은 같은 트랜잭션으로 저장하고, 이름·버전이 겹치면 기존 정보를 덮어쓰지 않고 거부한다.

## 상세와 평가 기록

버전 상세에서 기반 모델, 파일 위치, 해시, 메모와 평가·배포 기록을 확인한다.
평가하지 않은 수치는 미측정으로 표시한다.
**수동 평가 결과 등록**은 담당자가 별도로 확인한 결과를 기록하는 기능이지 평가 실행 버튼이 아니다.

평가 결과와 검토 이유를 입력하고, 종합 점수·JSON 준수·DB 판단·한국어 품질·평균 응답 시간·표본 수는
실제로 확인한 값만 기록한다. 화면에 기록한 점수를 자동 측정 정확도로 해석하지 않는다.
수동 통과 기록만으로 버전 상태를 검증 완료로 바꾸거나 운영 모델을 활성화하지 않는다.

## 웹 학습 작업

**학습 작업**에서 승인 자료를 이용한 시험 학습을 시작하거나 취소한다. 실제 실행은 AI 학습 서버에서 수행한다.
현재는 검증한 Qwen 구조의 마지막 층 MLP에 1~20회 업데이트하는 제한된 시험이다. 임의 모델의 범용 학습 API가 아니다.
자료 준비, 학습, 저장 어댑터 재로딩을 차례로 실행하며 운영 모델은 자동 전환하지 않는다.
서로 다른 원 요구사항 3그룹 이상이 필요하다. 짧은 학습·검증 자료 각 1그룹은 반드시 있어야 한다.
긴 시험 자료는 자르지 않고 제외하며 DB 정답 학습과 독립 생성 품질 평가는 수행하지 않는다.

사용 흐름은 `웹 → 백엔드 실행 기록 → 서명된 AI 학습 서버 요청 → 작업 실행 → 상태 조회`다.
백엔드 실행 환경에 다음 값을 설정한다. 내부 키나 실제 전송 키는 브라우저에 입력하거나 문서에 붙이지 않는다.

```dotenv
DOENAAI_TRAINING_RECEIVER_URL=http://학습서버주소:8011
DOENAAI_TRAINING_TRANSFER_KEY=기존에_두_서버가_공유한_전송키
DOENAAI_MODEL_MANAGER_ID=서로_다른_백엔드마다_고유한_이름
```

Spring 설정은 백엔드 프로세스의 환경변수를 읽는다. AI 서버의 `.env`나 `training/.env`를 자동으로 공유하지 않는다.
`DOENAAI_MODEL_MANAGER_ID`는 선택값이며 없으면 호스트 이름을 사용한다. 백엔드 간 이름이 겹치지 않게 설정하는 것을 권장한다.
AI 학습 서버는 `training/.env`의 `DOENAAI_TRAINING_MODEL_DIR`을 실제 로컬 모델 경로로 설정하고
업데이트한 `receiver_service.py`를 학습용 가상환경에서 재시작해야 한다. 기존 수신 키와 공유 NAS 설정은 유지한다.
모델 경로·환경이 준비되지 않았거나 서버 상태를 확인하지 못하면 시작을 막고 이유를 표시한다.

작업 식별자는 서버에 영속 저장하고 중복 시작을 막는다. 화면을 닫아도 시작한 작업은 계속된다.
활성 작업은 표시 중일 때 5초마다 확인하고 화면 숨김·종료·조회 오류 때 자동 조회를 중단한다.
취소는 해당 작업의 자식 프로세스만 중단하고 기존 모델·수신 원본·이전 산출물은 삭제하지 않는다.
서버 재시작으로 중단된 작업은 실패 이력으로 남기며 자동 재학습하지 않는다.
웹 워커끼리는 실행 잠금을 공유하지만 기존 독립 CLI 학습과 잠금을 공유하지 않으므로 동시에 실행하지 않는다.

별도로 실행한 CLI 학습은 웹 작업 목록에 없을 수 있다. 목록 부재만으로 학습이 실행되지 않았다고 판단하지 않는다.

## 분석 생성 모델별 학습 자료 분리

분석을 실제 생성한 모델을 `analysisModel`로 저장하고 승인 자료의 `sourceModel`로 전달한다.
이 값은 분석 시작 때 고정한 모델에서 가져오며 현재 화면 선택값으로 추정하지 않는다.
브라우저에서 생성 모델을 바꾸거나 기존 자료에 임의로 추가하면 검증·전송을 거부한다.
생성 모델 필드를 포함한 자료는 수신 서버가 `SOURCE_MODEL_V1`을 지원할 때만 게시한다.

현재 학습 서버는 `qwen3.8:27b`로 분석한 자료와 `mlx-community/Qwen3.8-27B-4bit` 기반 모델의
명시적 대응만 지원한다. 모델 계열 이름이 비슷하다는 이유로 다른 크기·버전을 자동 대응하지 않는다.
Gemma·EXAONE·Devstral 학습은 별도 실행 환경과 대응 검증을 구현하기 전까지 사용할 수 없다.

학습 작업 탭에는 학습 대상·고정 기반 모델 버전과 같은 생성 모델의 승인 자료 식별자만 표시한다.
다른 생성 모델 또는 생성 모델 기록이 없는 기존 자료는 제외한다. 기존 원본 파일은 수정하지 않는다.
학습 작업도 같은 생성 모델의 기록만 표시하며, 모델 기록이 없는 예전 작업은 실행 작업 이력에 보존한다.
학습 요청은 화면에서 확인한 모델과 기반 모델 식별값을 함께 보내고, 서버는 접수·실행 전에 다시 대조한다.
자료 사본을 만들 때도 같은 모델의 사례만 추리며 혼합 파일에서도 다른 모델 사례를 함께 복사하지 않는다.

기존 자료에 현재 모델을 임의로 붙여 사용하지 않는다. 생성 모델을 확인할 수 없는 자료는 새 코드로
다시 분석하고 검토·승인해 전달해야 한다. 반영에는 백엔드·AI 분석 서버·맥북 수신 서버의 최신 코드와
재시작이 필요하다. 이 패치는 실제 학습 시작이나 운영 모델 전환을 실행하지 않는다.

## 현재 사용 모델과 MLX 학습 모델의 자동 연결

학습 작업 조회 시 백엔드는 추론 서버의 현재 사용 모델을 확인하고 학습 컨트롤러에
같은 모델 식별자를 전달한다. 학습 서버는 `DOENAAI_TRAINING_MODELS_FILE`의 로컬 대응 설정
또는 기존 Qwen 전용 경로에서 MLX 기반 모델·고정 버전·지원 학습기를 확인한다.
웹에는 현재 사용 모델과 대응하는 학습 대상, 같은 생성 모델의 승인 자료를 표시한다.

학습 시작 직전 현재 사용 모델을 다시 확인하며, 모델 변경 전 화면에서 만든 시작 요청은
거부한다. 모델 대응이 없거나 등록한 학습기가 지원되지 않으면 실행을 막고 이유를 표시한다.
새 모델 조회는 이미 실행 중인 학습의 기반 모델을 변경하지 않는다. 등록만으로 모델을
다운로드하거나 학습을 시작하지 않는다. 현재 실제 학습 지원 범위는 Qwen MLP 시험 그대로다.

맥북 등록 파일 형식과 반영 순서는 [모델 호환성 설정](../training/MODEL_COMPATIBILITY.md)에 있다.

## 변경 이력과 통신 중단

`012_model_management_operations.sql`의 두 테이블을 사용한다.

- `model_management_operations`: 요청자, 작업 종류, 대상 서버 식별값, 변경 전후 모델, 현재 결과와 오류 코드.
- `model_management_events`: 요청 접수와 이후 확인된 상태·진행률 변경을 추가 방식으로 보존한다.

실행 요청을 DB에 먼저 확정한 뒤 원격으로 보낸다. DB에 기록하지 못하면 실행하지 않는다.
이력 수정·삭제를 막는 트리거와 실행 기록 외래키로 연결을 보존하며 브라우저의 직접 테이블 접근을 차단한다.
사용자 계정이 삭제돼도 당시의 사용자 식별자는 남긴다. 비밀키·학습 원문·원격 오류 원문은 남기지 않는다.
시험 토큰은 원문 대신 요청 일치 확인용 해시만 저장하며 API 응답의 짧게 쓰는 토큰은 브라우저 메모리에만 둔다.

응답이 끊기면 실패로 단정하지 않고 **결과 확인 필요**로 표시한다. 실행 이력에서 같은 식별자로 결과를 조회한다.
상태 조회는 원격 실행을 반복하지 않는다. 사용자가 같은 요청을 명시적으로 재시도할 때만 원격 멱등 API로 같은 식별자를 전송한다.
다른 백엔드의 기록은 현재 서버에서 재실행하거나 임의의 다른 AI 서버에 조회하지 않는다.
상태 변경 이력은 백엔드가 실제로 확인한 시점의 기록이다. 화면이 닫혀 있던 동안의 모든 원격 중간 상태를 복원하는 것은 아니다.

## 등록 파일의 배포 준비

배포 준비 화면은 파일 수신, 실제 해시 대조, 실행 환경 호환성, 자동 평가, 배포 승인, 서버 전환을 구분한다.
등록 파일을 자동으로 수신·변환해 직접 배포하는 기능은 제공하지 않으며 불가 이유를 화면에 표시한다.
공유 NAS 모델 전달 방침은 `training/MODEL_DELIVERY.md`를 참고한다.
설치된 Ollama 모델의 전환·복구와 이 등록 파일의 직접 배포는 별도다.

## 권한과 API

| 작업 | API | 필요한 권한 |
| --- | --- | --- |
| 관리 목록 | `GET /api/models` | `MODEL_READ` |
| 실제 모델 상태 확인 | `GET /api/models/runtime` | `MODEL_READ` |
| 버전 상세 | `GET /api/models/versions/{id}` | `MODEL_READ` |
| 버전 등록 | `POST /api/models/versions` | `MODEL_TRAIN` 또는 `MODEL_DEPLOY` |
| 수동 평가 기록 | `POST /api/models/versions/{id}/evaluations` | `MODEL_EVALUATE` |
| 설치 모델 목록 | `GET /api/models/installed` | `MODEL_READ` |
| 짧은 JSON 시험 | `POST /api/models/probe` | `MODEL_DEPLOY` |
| 모델 전환 | `POST /api/models/activate` | `MODEL_DEPLOY` |
| 직전 모델 복구 | `POST /api/models/rollback` | `MODEL_ROLLBACK` |
| 학습 작업 조회 | `GET /api/models/training` | `MODEL_READ` |
| 학습 시작·취소 | `POST /api/models/training`, `POST /api/models/training/{id}/cancel` | `MODEL_TRAIN` |
| 실행 이력·상세 | `GET /api/models/operations`, `GET /api/models/operations/{id}` | `MODEL_READ` |

현재 로그인한 사용자를 등록자·평가자로 기록하며, 화면에서 버튼을 숨기는 것과 별개로 API에서도 권한을 검사한다.
각 목록은 최신 100건까지 반환하고 일부를 생략하면 표시한다. 상세 평가·배포 기록도 같은 방식으로 제한한다.
검색은 불러온 범위에 적용되므로 전체 저장 기록의 검색으로 해석하지 않는다.

버전 등록·수동 평가는 기존 `003_ai_model_training.sql`, 새 실행 기록은 `012_model_management_operations.sql`을 사용한다.
새 코드 적용에는 백엔드·AI 분석/추론 서버·AI 학습 서버 재시작과 프론트 빌드 반영이 필요하다.

## 이번 확인 범위

2026-10-21 사용자 승인으로 백엔드를 재시작하고 Safari에서 실제 Qwen 상태 응답과 관리 목록 조회를 확인했다.
라이트·다크 모드, 390×844 화면, 모델 버전 등록 창의 항목과 배치를 확인했다.
실제 업무 DB에 시험용 등록·평가 기록은 만들지 않았다. 저장 동작은 자동 검사로 확인했으며,
별도 폐기 DB를 사용하는 선택형 통합 검사는 환경 설정이 없어 실행하지 않았다.

추가 구현 뒤 백엔드 256개, AI 서버 188개, 학습 도구 127개, 프론트 138개 검사가 통과했다.
외부 DB 선택형 15개와 기존 AI 검사 3개는 건너뛰었다. 프론트 린트·빌드가 통과했고 큰 번들 경고는 남아 있다.
사용자가 12번 SQL을 직접 적용한 뒤 읽기 전용으로 테이블·제약·인덱스·접근 차단·추가 전용 트리거를 확인했다.
사용자 승인으로 이 Mac의 백엔드와 AI 분석/추론 서버를 재시작했다. 실제 설치 목록 API는 200으로
EXAONE·Gemma·Qwen·Devstral 네 모델을 반환했고 Safari 선택 목록에도 표시됐다.
현재 Qwen 선택은 유지했으며 실제 JSON 시험·모델 전환·학습 시작·학습 서버 재시작은 실행하지 않았다.
