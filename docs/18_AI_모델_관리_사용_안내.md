# AI 모델 관리 사용 안내

## 화면과 실제 사용 모델

**AI 모델 관리**는 스튜디오의 AI 분석/추론 서버와 맥북 학습 서버의 모델·작업을 제어합니다.
설치 모델, DB에 등록한 버전 정보, 실제 실행 작업은 각각 확인할 수 있습니다.
모델 버전·배포 이력은 관리 기록이며, 현재 사용 모델은 스튜디오의 AI 분석/추론 서버의 실제 선택 상태로 확인합니다.

상단의 **모델 작업**에서 설치 모델을 선택한 뒤 실행할 작업을 고릅니다.
목록은 연결된 서버의 모델 실행 환경을 기준으로 하며, 브라우저를 연 PC의 설치 목록이 아닙니다.

## 분석에 사용할 모델 변경

1. **모델 작업 → 분석에 사용**에서 대상 모델을 선택합니다.
2. **JSON 응답 검증**으로 짧은 한국어 응답 형식을 시험합니다.
3. 유효한 검증 결과와 적용 범위를 확인하고 모델 변경을 실행합니다.
4. 필요한 경우 **이전 모델로 복구**에서 직전 선택으로 한 번 되돌립니다.

검증은 기본 5분 동안 유효하며 모델 파일 식별값과 선택 설정 버전에 묶입니다.
시험 뒤 파일·선택 상태가 바뀌면 다시 검증합니다. 새 선택은 새 분석부터 적용하고,
진행 중인 분석은 시작한 모델로 마무리합니다. 짧은 JSON 검증과 업무 품질 평가는 별도입니다.

선택 상태는 스튜디오의 AI 분석/추론 서버의 `.runtime/model-selection.sqlite3`에 보존합니다.
`DOENAAI_AI_MODEL`은 최초 기본값이며 저장된 선택을 덮어쓰지 않습니다.
스튜디오에서 여러 AI 분석/추론 서버 프로세스가 같은 선택을 제어할 때는 같은 상태 파일을 사용합니다.

## 선택 모델 학습

**모델 작업 → 선택 모델 학습**에서 대응 기반 모델·고정 버전·승인 자료를 확인하고 시작합니다.
진행률·결과·학습 취소는 **실행 작업 이력**에서 확인합니다.
웹 요청은 1~20회 업데이트의 시험 학습입니다. 기존 Qwen 마지막 층 MLP 시험기와 공통 `mlx-lora-v1`을 지원하며,
선택 모델에 대응하는 MLX 가중치·고정 버전·학습 프로필을 맥북 학습 서버에 등록해야 합니다.
화면에서 학습 조건과 이어 학습 여부, 완성 모델 변환 지원 여부를 확인합니다.

분석을 생성한 모델은 분석 시작 때 고정하고 승인 자료의 `sourceModel`로 전달합니다.
학습한 새 모델의 결과에는 원래 기반 계열과 `sourceTrainedModel`의 모델·파일 식별값도 보존합니다.
실제 선택 모델은 `selectedModel`로 유지하며 승인 자료는 등록한 기반 계열의 `sourceModel`과 일치해야 합니다.
다른 기반 계열 또는 출처 미기록 자료는 제외합니다.
화면 선택값으로 출처를 추정하거나 기존 자료에 임의로 붙이지 않습니다.

완료한 파생 모델을 선택하면 이 맥북에 보존한 부모 작업·어댑터·설정·기반 파일을 검증한 뒤 이어 학습합니다.
부모 어댑터를 읽고 새 작업의 결과를 만들며 기존 어댑터를 덮어쓰지 않습니다.

맥북 학습 서버는 모델 대응을 조회하고 실행 전에 다시 검증합니다. 미등록 모델·지원하지 않는 학습기는 시작을 막습니다.
설치·추론 가능 여부, 학습 지원, GGUF 변환 지원은 각각 확인합니다.
실제 대형 모델의 학습·변환은 기존 Qwen 경로에서 확인했으며, 작은 Llama·EXAONE4의 CPU 학습·이어 학습 검사는
실제 대형 EXAONE 등의 학습·전체 변환·업무 품질 검증을 대신하지 않습니다.
자료 수·분할·정답 검토 기준은 [학습 자료 흐름](../training/DATA_WORKFLOW.md),
대응 설정은 [모델 호환성](../training/MODEL_COMPATIBILITY.md)을 확인합니다.

## 학습 결과로 새 모델 생성·적용

1. **모델 작업 → 학습 결과 적용**에서 같은 모델의 완료된 웹 학습을 선택합니다.
2. **준비 상태 새로고침**으로 맥북 학습 서버의 변환 도구·저장 공간·진행 작업을 확인합니다.
3. **새 학습 모델 생성**을 요청합니다. 맥북이 기반 모델과 어댑터를 병합하고 GGUF 변환·Q4_K_M 양자화 후
   서명된 완성 모델을 NAS에 게시합니다. 완료한 학습을 재사용하므로 다시 학습할 필요는 없습니다.
4. 생성이 `SUCCEEDED`이면 **분석 서버에 새 모델 등록**을 요청합니다.
5. 등록이 `READY`이면 **새 모델 응답 검증 → 새 학습 모델 적용**을 진행합니다.

생성 상태는 `PENDING → FUSING → CONVERTING → QUANTIZING → PUBLISHING → SUCCEEDED`입니다.
등록 상태 `WAITING`은 공유 파일이 아직 모두 도착하지 않았다는 뜻입니다.
NAS 동기화가 끝나면 같은 결과에서 등록을 다시 요청합니다. 등록만으로 현재 모델이 전환되지는 않습니다.

화면을 닫아도 접수한 작업은 서버에서 계속됩니다. 표시 중인 활성 작업은 5초마다 조회하며
화면 숨김·조회 오류 때 자동 조회를 멈춥니다. 통신이 끊기면 기존 상태부터 확인하고 새 작업을 중복 생성하지 않습니다.
학습과 새 모델 생성은 작업 잠금을 공유합니다. 독립 CLI 작업도 동시에 실행하지 않습니다.
생성 취소·실패 때 원래 기반 모델·학습 어댑터·수신 원본은 보존하고 일회성 변환 파일을 정리합니다.

새 모델은 `doenaai-trained:web-<학습 작업 ID>`로 별도 등록합니다.
실제 설치 파일 식별값까지 일치해야 검증·적용할 수 있습니다.
서명·파일 해시 검증과 실제 업무 품질 평가는 별도입니다.

## 서버 준비

백엔드에는 스튜디오의 AI 분석/추론 서버 주소·내부 키와 다음 학습 호출 설정이 필요합니다.
실제 값은 서버 로컬 설정에서 관리하고 브라우저·문서·Git에 넣지 않습니다.

| 설정 | 역할 |
| --- | --- |
| `DOENAAI_TRAINING_RECEIVER_URL` | 맥북 학습 서버 API 주소 |
| `DOENAAI_TRAINING_TRANSFER_KEY` | 자료·완성 모델 전달과 호출에 쓰는 공유 키 |
| `DOENAAI_MODEL_MANAGER_ID` | 선택형 백엔드 식별자, 미설정 시 호스트 이름 사용 |

장비별 `.env`는 자동 공유되지 않습니다. 맥북에는 MLX 학습 기반 모델과 고정 변환 도구,
작업 폴더의 여유 공간 **180 GiB 이상**이 필요합니다.
스튜디오의 AI 분석/추론 서버에는 기존 모델 실행 환경과 동기화 폴더·같은 전달 키가 필요하며 MLX 설정은 필요하지 않습니다.
설치·환경변수를 바꾼 서버는 진행 작업을 확인한 뒤 재시작합니다.
자세한 준비·복구 절차는 [완성 모델 생성](../training/MODEL_EXPORT.md)을 따릅니다.

## 버전 등록·평가·실행 이력

**모델 버전 등록**은 이름·기반 모델·파일 상대경로·해시·자료 설명을 DB에 기록합니다.
파일을 복사하거나 실제 사용 모델을 바꾸지는 않습니다. 같은 모델에 다음 버전을 추가할 수 있으며
중복 이름·버전은 덮어쓰지 않습니다. 임의 등록 파일의 배포 준비 화면은 확인되지 않은 조건을 표시합니다.
완료한 웹 학습의 실제 생성·등록·적용은 위 **모델 작업** 흐름을 사용합니다.

버전 상세의 **수동 평가 결과 등록**은 사람이 확인한 수치·근거를 기록합니다.
미측정 값은 채우지 않으며 수동 통과 기록만으로 실제 모델을 활성화하지 않습니다.

설치 모델 시험·전환·복구와 학습 시작·취소 요청은 DB 실행 기록과 추가 상태 이력에 남깁니다.
응답 유실 때는 **실행 작업 이력**에서 같은 식별자로 확인합니다.
새 모델 생성·등록의 진행 상태는 맥북 학습 서버와 스튜디오의 AI 분석/추론 서버에 보존되며 **학습 결과 적용**에서 다시 조회합니다.
다른 백엔드의 실행 기록을 현재 서버에서 임의로 재실행하지 않습니다.

## 권한과 API

| 작업 | 백엔드 API | 권한 |
| --- | --- | --- |
| 모델·버전·실제 상태 조회 | `GET /api/models`, `/api/models/versions/{id}`, `/api/models/runtime` | `MODEL_READ` |
| 버전 등록 | `POST /api/models/versions` | `MODEL_TRAIN` 또는 `MODEL_DEPLOY` |
| 수동 평가 기록 | `POST /api/models/versions/{id}/evaluations` | `MODEL_EVALUATE` |
| 설치 모델·학습·실행 이력 조회 | `GET /api/models/installed`, `/api/models/training`, `/api/models/operations` | `MODEL_READ` |
| JSON 검증·전환 | `POST /api/models/probe`, `/api/models/activate` | `MODEL_DEPLOY` |
| 직전 모델 복구 | `POST /api/models/rollback` | `MODEL_ROLLBACK` |
| 학습 시작·취소 | `POST /api/models/training`, `/api/models/training/{id}/cancel` | `MODEL_TRAIN` |
| 생성·등록 상태 조회 | `GET /api/models/trained/{id}/build`, `/api/models/trained/{id}/import` | `MODEL_READ` |
| 새 모델 생성·취소 | `POST /api/models/trained/{id}/build`, `/api/models/trained/{id}/build/cancel` | `MODEL_TRAIN` |
| 스튜디오의 AI 분석/추론 서버 등록 | `POST /api/models/trained/{id}/import` | `MODEL_DEPLOY` |

화면 표시와 별개로 API에서도 권한을 검사합니다.
관리 정보는 `003_ai_model_training.sql`, 실행 기록은 `012_model_management_operations.sql`을 사용합니다.
목록은 최대 100건이며 생략 여부를 표시합니다. 검색은 불러온 범위에 적용됩니다.
