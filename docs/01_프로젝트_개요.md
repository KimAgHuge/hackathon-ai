# 1. doenaai 프로젝트 개요

최종 갱신: 2026-07-30

이 문서는 `doenaai`가 어떤 프로젝트인지, 어떤 기술을 사용하며 저장소가 어떻게
구성되는지를 설명하는 공식 기준 문서다.

- 시스템 간 배치와 통신 흐름: `docs/02_시스템_아키텍처.md`
- 실제 구현 완료 상태와 다음 작업: `docs/03_현재_진행상황.md`

실제 토큰, 비밀번호, Supabase 키, Git/DB credential, 암호화 키, 내부 AI API
key는 문서나 Git에 기록하지 않는다.

## 1. 프로젝트 정의

`doenaai`는 고객 요구사항을 프로젝트의 프런트엔드, 백엔드, SQL,
데이터베이스 스키마와 연결해 영향 범위와 기술 위험을 분석하고, PM과 PL이
예상 작업량·기간·비용 근거를 갖춘 견적을 작성하도록 돕는 AI 기반 프로젝트
견적 지원 플랫폼이다.

단일 회사 전용 도구로 한정하지 않는다. 여러 회사와 조직이 사용할 수 있는
서비스형 제품과 고객 환경에 별도로 설치하는 구축형 제품을 모두 지향한다.
AI가 견적을 자동 확정하는 것이 아니라 분석 근거와 초안을 제공하고, 최종 범위와
견적은 PM과 PL이 개발자 검토를 거쳐 결정한다.

대표적인 분석 경로:

```text
Vue 화면
  -> HTTP API
  -> Spring Controller
  -> Service
  -> Repository 또는 MyBatis Mapper
  -> SQL
  -> DB 테이블과 컬럼
```

프로젝트가 제공하려는 결과:

- 고객 요구사항의 구조화된 접수와 변경 이력
- 화면부터 DB까지 이어지는 통합 아키텍처
- 특정 테이블을 사용하는 화면/API의 역방향 탐색
- 고객 요구사항이 영향을 주는 파일, API, SQL, 테이블, 컬럼
- 변경 위험도와 판단 근거
- 예상 작업 항목, 작업량과 기간 범위
- 견적의 가정, 제외 범위, 위험 여유와 판단 근거
- 권장 수정 순서와 테스트 항목
- PM·PL·개발자가 검토·수정·승인한 최종 분석 결과와 견적 초안
- 고객에게 공개 가능한 범위로 정리한 조회용 결과
- 승인 결과를 활용한 향후 AI 모델 개선

## 2. 해결하려는 문제

PM과 PL이 고객 요구사항을 접수해 견적을 만들 때 요구가 불완전하거나 기술적인
영향 범위가 보이지 않는 상태에서 경험에 의존해 작업량과 기간을 산정하는 경우가
많다. 소스와 DB가 분리되어 관리되는 프로젝트일수록 누락 위험이 커진다.

- 고객의 자연어 요구를 실제 변경 범위와 연결하기 어려움
- 하나의 화면 변경이 어떤 API, SQL, DB에 영향을 주는지 찾기 어려움
- 개발자의 경험과 가용 여부에 따라 견적 편차가 큼
- 숨은 연동, 데이터 이관, 회귀 테스트가 빠져 일정과 비용이 초과될 수 있음
- 고객에게 작업량과 기간 산정 근거를 설명하기 어려움
- PL과 개발자가 확인한 기술 위험이 견적서에 체계적으로 반영되지 않음
- 분석 결과와 실제 수행 결과가 다음 견적을 위한 자산으로 축적되지 않음

`doenaai`는 정적 분석과 DB 메타데이터로 기술 관계를 먼저 만들고, AI가 그
근거를 바탕으로 영향 범위, 위험, 작업 항목, 예상 작업량과 기간 범위를 제안하도록
설계한다. PM과 PL은 제안을 검토해 고객에게 전달할 견적을 완성한다.

대표 업무 흐름:

```text
고객 요구사항 전달
  -> PM/PL 요구사항 접수와 구체화
  -> 프로젝트 소스·DB 기준선 확인
  -> 영향 범위와 기술 위험 분석
  -> 작업 항목·예상 작업량·기간 범위 산정
  -> PL/개발자 기술 검토
  -> PM 견적 초안 작성과 확정
  -> 고객 제한 조회
```

## 3. 핵심 원칙

### 근거 우선

LLM이 저장소 파일명을 보고 관계를 추측하지 않는다. 정적 분석기가 다음 사실을
먼저 수집한다.

- 파일과 모듈
- 언어와 프레임워크
- API method/path
- 클래스와 메서드
- Mapper와 SQL
- DB 스키마, 테이블, 컬럼, PK/FK, 인덱스
- 각 관계의 파일 경로와 코드 위치

AI는 이 구조화된 사실을 요약하고 변경 위험과 권장사항을 설명한다.

### 재현 가능한 분석

분석 요청에는 가능한 경우 다음 값을 snapshot으로 남긴다.

- 프로젝트
- 저장소 URL
- branch
- commit SHA
- DB schema
- 분석 옵션
- 사용 모델 버전
- 분석 시작/완료 시간

### 비동기 처리

대규모 저장소 분석은 HTTP 요청 하나에서 동기 처리하지 않는다.

```text
작업 생성
  -> Worker 선점
  -> 단계별 진행률
  -> 결과 저장
  -> 완료 또는 실패
```

### 사람 검토

AI 결과는 자동으로 정답 처리하지 않는다.

```text
AI 원본 결과
  -> PM/PL/개발자 검토
  -> 수정 결과
  -> 승인
  -> 향후 학습 데이터 후보
```

### Provider 중립성

특정 Git 또는 AI provider에 고정하지 않는다.

- GitHub
- GitLab
- Bitbucket
- Yona
- 자체 구축 Git
- Ollama
- 향후 MLX inference server 또는 외부 AI API

## 4. 주요 사용자

### PM

- 고객과 프로젝트 관리
- 고객 요구사항 접수, 정리, 범위 조정
- 영향 분석 요청과 결과 확인
- 작업 항목, 예상 작업량, 기간, 비용 근거 작성
- 가정·제외 범위·위험 여유를 포함한 견적 버전 관리
- 고객에게 공개할 결과와 견적 승인

### PL

- 프로젝트 기술 기준선과 분석 범위 설정
- 소스 저장소와 분석 대상 DB 연결
- 영향 범위, 기술 위험, 구현 순서 검토
- 작업 분해와 작업량·기간 산정 검토
- 개발자 의견을 취합해 PM의 견적 작성을 지원

### 고객

- 자신에게 허용된 프로젝트와 요구사항 조회
- 영향 요약, 예상 일정, 견적과 전제조건 조회
- 의견 전달과 확인

고객에게는 Git/DB credential, 원본 소스, 내부 분석 프롬프트와 다른 고객의
정보를 기본적으로 공개하지 않는다.

### 개발자

- 통합 아키텍처와 분석 근거 조회
- 관련 파일, API, SQL, DB 영향 범위 확인
- 구현 난이도, 기술 부채, 회귀 위험과 테스트 범위 검토
- 작업 항목과 작업량 산정에 기술 의견 제공

### 운영 지원 역할

시스템 관리자와 모델 운영자는 제품 운영을 지원하는 역할이며 핵심 업무 사용자는
아니다.

- 사용자, 조직, 역할과 권한 관리
- Git host와 보안 정책 관리
- AI/학습 서버와 모델 버전 관리
- 승인 결과를 활용한 데이터셋, 평가와 배포 관리

## 5. 기술 스택

### Frontend

| 구분 | 기술 |
|---|---|
| Framework | Vue 3.5 |
| Build | Vite 6.2 |
| Router | Vue Router 4.5 |
| State | Pinia 3.0 |

Node.js 버전은 저장소에 아직 고정되어 있지 않다. 이후 `.nvmrc` 또는
`package.json`의 `engines`로 지원 버전을 명시하는 것이 좋다.

### Backend

| 구분 | 기술 |
|---|---|
| Language | Java 25 |
| Framework | Spring Boot 4.1.0 |
| Security | Spring Security, OAuth2 Resource Server |
| Persistence | Spring Data JPA, Spring JDBC |
| Git | Eclipse JGit 7.7 |
| Main DB Driver | PostgreSQL JDBC |
| Analysis DB Driver | Oracle JDBC, PostgreSQL JDBC |
| Build | Gradle Wrapper |

DB schema는 Hibernate 자동 생성이 아니라 Supabase migration SQL로 관리하며
Hibernate는 schema validation 용도로 사용한다.

### AI Server

| 구분 | 기술 |
|---|---|
| Language | Python |
| API | FastAPI 0.128.8 |
| Validation | Pydantic 2.13.4 |
| Settings | pydantic-settings 2.11 |
| Model Client | Ollama Python 0.6.2 |
| HTTP | httpx 0.28 |
| Test | pytest 8.4 |
| Manifest Parsing | PyYAML, tomli, 표준 XML/JSON parser |

새로운 환경은 Python 3.11 이상을 권장한다. Mac Studio에서는 시스템 Python
3.9.6으로 17개 테스트가 통과했지만 `.venv`를 사용한다.

### Local Model Runtime

| 구분 | 기술 |
|---|---|
| Host | Apple M1 Max Mac Studio, 64GB 통합 메모리 |
| Runtime | Ollama |
| Initial Model | Devstral (`devstral:latest`, 14GB) |
| Binding | `127.0.0.1:11434` 전용 |

기준 Mac Studio에서 Devstral 설치, 구조화 JSON 단독 추론, FastAPI 실제 호출과
연결 실패·모델 미설치·timeout 오류 변환까지 검증했다. Ollama와 모델 파일은
Git에 포함하지 않는다.

### Training Server

| Runtime | Python, MLX-LM |
| Training | LoRA |
| Input | 승인된 분석 결과 기반 JSONL |
| Output | adapter, merged artifact, 평가 결과 |

학습 기능은 현재 placeholder이며 실제 구현 전이다.

### Platform and Data

## 7. Frontend 구조와 작성 규칙

### 인증과 API

- Supabase SDK는 로그인과 session 복원에 사용한다.
- Axios interceptor가 access token을 Spring API에 Bearer token으로 전달한다.
- `VITE_USE_MOCK=false`일 때 실제 API를 호출한다.
- 프런트 permission 표시는 사용자 편의를 위한 UI 제어다.
- 최종 권한 검사는 반드시 Spring Boot에서도 수행한다.

### Base 컴포넌트

```text
BaseButton
BaseCard
BaseInput
BasePagination
BaseSelect
BaseTable
BaseTextarea
```

공통 컴포넌트는 공통 구조·디자인·동작과 props/event/slot만 책임진다. API 호출,
검색 조건, 화면별 상태는 View 또는 Store가 담당한다.

### Common과 Layout

```text
PageTitle
StatusBadge
StepHeader
ViewHeading
AppHeader
AppSidebar
```

### 공통 테이블

`BaseTable`은 다음 기능을 제공한다.

- 컬럼 정의
- 동적 cell slot
- 선택
- 행 클릭
- 정렬 이벤트
- 고정 header

|---|---|
| `organizations` | 서비스를 사용하는 회사·조직 구분 |

| `requirements` | 요구사항 식별자, workflow 상태와 고객 공개 여부 |

## 10. 보안 원칙

- Git token/password/private key를 평문 저장하지 않음
- DB password를 평문 저장하지 않음
- Spring Boot에서 AES-256-GCM 암호화
- 조회 API에서 비밀값과 암호문을 반환하지 않음
- Git URL에 username/token을 포함하는 방식 거부
- Git host allowlist로 SSRF 위험 제한
- DB 연결은 가능한 경우 read-only
- Ollama는 Mac localhost에만 공개
- FastAPI 분석 API는 내부 API key 필요
- credential을 LLM prompt에 포함하지 않음
- 브라우저 환경변수에는 publishable key만 사용
- Supabase secret/service role key는 프런트에 넣지 않음
- 조직별 데이터 격리와 서버 측 tenant 권한 검증
- 고객은 허용된 프로젝트·요구사항·견적만 조회
- 고객 화면에서 원본 소스와 내부 분석 상세를 기본 차단
- AI 산정값을 자동 확정하지 않고 PM/PL 검토를 필수화
