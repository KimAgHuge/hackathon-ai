# 승인 자료를 사용한 맥북 시험 학습

기준일: 2026-10-21 · 시작 코드: `71aab78` · 최종 코드 기준: `27d3436` · 장비: MacBook Pro M4 Max·64GB

## 자료 확인과 분리

iCloud Drive의 `17_2026-10-21_빠른_학습_인수인계.md`를 읽고, 실제 수신함의
3개 파일·3건을 다시 검증했다. SHA-256·크기·승인·비식별 표시·현재 응답 계약과
정적 근거 검사를 통과했다. 사례 ID·동일 분석 입력은 중복되지 않았고, 같은 프로젝트의
서로 다른 원 요구사항 ID 3개였다. 승인 여부는 제공자의 검토 기록이며 자동 검사가
업무 정답의 의미를 보증하지는 않는다.

원 요구사항 ID와 프로젝트 그룹을 함께 사용해 분리한다. 같은 요구사항의 수정 버전과
후속 질문은 대표 사례와 같은 분할로 묶으며 서로 다른 분할에 배정하면 거부한다.
실제 사례 원문·식별자 배정표·토큰·학습 산출물은 Git에서 제외한 로컬 폴더에 저장한다.

| 분할 | 사용한 자료 | 처리 |
|---|---|---|
| 학습 | 새로 수신한 목표 완료일 요구사항의 일반 정답 | 전체 10,559토큰·정답 1,098토큰을 보존해 사용 |
| 검증 | 다른 원 요구사항의 일반 정답 | 전체 16,027토큰·정답 1,531토큰을 보존해 손실 측정 |
| 시험 | 나머지 원 요구사항의 일반 정답 | 27,226토큰으로 이번 18,000 상한을 넘어 자르지 않고 보관 |
| DB 단계 | 승인된 DB 정답 2건 | 운영의 분할 호출별 입력·정답을 복원하지 못해 이번 학습에서 제외 |

## 입력·실행 조건

시작 당시 학습 변환기는 일반 단계에 DB 상세를 모두 넣고 있었다. 당시 로컬 분석 코드와
같은 테이블 개요 변환으로 맞춘 버전 2로 시험 학습·재로딩을 완료하고 결과를 보존했다.
작업 중 저장소에 `27d3436`까지 반영되어 인수인계가 언급한 `source_context.py`,
`database_scope.py`, 메시지 버전 3과 `DATABASE_REVIEW_PLAN_V1`이 들어왔다.
사용자의 최신 코드를 유지하고 버전 3으로 자료를 새 경로에 다시 준비해 최종 시험했다.

현재 운영과 공유하는 변환을 그대로 사용하고 두 입력 변환 파일의 해시를 계약에 포함한다.
원본 수신 파일은 변경하지 않는다. 운영 변환에는 참조 수·글자 수 제한이 있으므로 실제
변환된 메시지에서 정답의 파일·줄 근거를 다시 검사한다. 생략된 81번째 참조를 인용하면
거부하는 회귀 검사도 추가했다. 실제 세 사례의 인용 근거는 모두 변환 후 검사에 통과했다.
실행 길이 상한 때문에 메시지나 정답을 추가로 자르지 않으며, 최종 정리의 내부 응답을
일반·DB 정답에 추가하지 않는다.

- 모델: 기존 MLX 4bit 모델, revision `10c35caafbb80f7dc6a7a432cdd11af10a6d4818`
- 마지막 1개 층의 MLP 3개 모듈, LoRA rank 4·scale 8·dropout 0, batch 1, Adam 학습률 `1e-5`
- 목표: 10회 업데이트, 고정 문맥 재사용, 새 `trial-` 어댑터 경로
- `thinking=false`를 명시하고 전체 대화와 프롬프트의 토큰 접두부가 같은지 확인
- 입력 전체의 고정 문맥을 계산한 뒤 손실에 쓰는 정답 위치만 MLP·정규화·출력층에 적용
- 짧은 입력에서 공식 손실·정답 위치 투영·문맥 재사용의 손실값·gradient 차이가 모두 0인지 확인

첫 실행은 고정된 선형 어텐션 층까지 순차 학습 경로를 써 업데이트 전에 중단했다.
고정된 앞 63개 층은 추론 커널을 사용하고 마지막 학습 층만 학습 모드로 두어 재실행했다.
고정 파라미터에는 미분 경로가 없음을 소스로 확인했고 변경한 경로에서도 공식 손실과
gradient의 동치 검사를 통과했다. 이 두 번째 시도는 2회 업데이트까지 진행했지만
순간 GPU 메모리가 약 59.09 GiB였고 시스템 스왑도 증가해 중단했다.
마지막 층의 어텐션도 고정하고 MLP만 학습하도록 범위를 줄여 세 번째 시도를 실행했다.
전체 문맥은 한 번 계산해 재사용하고, 위치별 MLP의 정답 손실만 반복 계산한다.
모든 중단 기록과 경로는 덮어쓰지 않고 별도로 남겼다.

| 자동 검사 | 학습 도구 73개와 AI 160개 통과, Python 문법·공백·한자 검사 통과 |

AI 검사는 샌드박스에서 157개 통과·로컬 포트 검사 3개 건너뜀 후, 해당 HTTP 검사만
허용된 환경에서 다시 실행해 3개 모두 통과했다. 사용 중단 예정 라이브러리 경고 1개는 남는다.

실행 경로는 다음과 같으며 모두 Git에서 제외한다.

- 최종 어댑터: `training/adapters/trial-20261021-7srnohr-v3/`
- 최종 데이터·보고서: `training/outputs/trial-20261021-7srnohr-v3/dataset/`
- 위 폴더의 `training-report.json`, `reload-report.json`, `training-steps.jsonl`
- 버전 2 성공 결과: `training/adapters/trial-20261021-7srnohr-mlp/`와 같은 이름의 출력 폴더

버전 2 성공 결과도 10회 업데이트·재로딩이 완료됐으며 약 162.03초·최대 17.1022 GiB였다.
서로 다른 메시지 계약의 손실을 직접 비교하지 않는다. 고정 문맥 재사용을 포함한 세 손실
계산 경로의 손실값·gradient 차이는 확인 입력에서 모두 0이었고 실제 업데이트도 유한했다.
손실 하락은 작은 자료의 관찰값이며 업무 정답 품질 개선을 확정하지 않는다.

## 결과의 범위

이 시험은 승인 자료로 학습·저장·재로딩이 가능한지 확인하는 단계다. 독립 시험 자료는
이번 길이 상한에서 실행하지 않았으므로 품질 개선이나 실무 합격을 판정하지 않는다.
Ollama 변환·등록·배포·운영 모델 전환도 수행하지 않는다. 별도 생성 평가와 사람 검토,
원격 최신 코드의 메시지 계약 일치를 확인한 뒤 업무 학습·배포를 판단해야 한다.
