# 3. doenaai 현재 진행상황

기준일: 2026-10-15 · 최신 원격 기준: `35f7a6a` · 병합 확인: `011576f` · 프로젝트 보완: `d5fee1a` · 회귀 테스트: `fcc2cd7` · 최초 전체 점검 기준: `adbd9c7`

**프로젝트 연결→근거 수집→AI 분석→결과 저장·조회 경로와 MacBook 학습 준비는 구현됐다.**
프런트 전체 화면과 검토·견적·고객 공개 업무가 완성된 제품은 아니다.
최초 MacBook 전체 점검에서는 코드·API 계약과 자동 검사만 확인했다. 이후 Mac Studio에서 Git 수집·AI 프롬프트·진행 화면을 변경하고 실제 분석 결과를 확인했다. **새 이력·근거 재사용·취소 코드는 단위/빌드 검사까지만 완료했으며 실DB·브라우저 검증은 아직이다.**
화면·API·DB 테이블 존재와 제품 기능 완료를 구분한다.

과거 8월의 “Worker·조직·요구사항 API 미구현” 기록은 현재 상태와 맞지 않아
[과거 기록](archive/03_2026-08-10_현재_진행상황.md)으로 분리했다.
9월·10월의 장비별 실연결 시험은 당시 검증으로 보존하며 현재 운영 상태를 보증하지 않는다.

### MacBook에서 이어받을 때 먼저 읽을 것

1. 이 문서에서 **완료/미완료와 다음 작업**을 확인한다.
2. Frontend를 변경한다면 [13번 Frontend 점검](13_2026-10-14_Frontend_구현_점검.md)의 화면별 계약·우선순위를 읽는다.
3. 분석 결과를 검토하거나 요구사항을 수정한다면 [Qwen 실제 분석 검토](evaluation/2026-10-14_qwen_실제_전체분석_검토.md)를 읽는다. 기존 결과는 **미승인**이다.
4. 학습 도구를 이어간다면 [12번 MacBook 진행상황](12_2026-10-14_MacBook_학습_도구_진행상황.md)과 [`training/DATA_WORKFLOW.md`](../training/DATA_WORKFLOW.md)를 읽는다. 제품 목적·서버 역할은 [7번 온보딩](07_팀원_온보딩_프로젝트_설명.md)을 참고한다.

먼저 각 장비에서 `git status -sb`와 `git log -1 --oneline`으로 작업 트리·기준 커밋을 확인한다. 이 문서의 커밋 이후에는 **실제 코드와 최신 커밋이 우선**이다. Mac Studio의 `.env`·로컬 설정·토큰·DB 비밀번호·모델 파일은 Git으로 전달하지 않는다.

## 2. 실제 구현된 분석 흐름

```text
프로젝트 등록: 조직 선택/생성 → 프로젝트 저장 → Git·DB 연결 시험/저장
변경 분석: 프로젝트별 변경요청 테이블 검색 → 필요 시 등록 폼에서 Git 프로젝트 선택·요구사항/첫 버전 생성 → 현재 버전 ID 선택
공통: 분석 작업 PENDING → Worker 선점 RUNNING
  → 고정 Git commit 읽기 → 읽기 전용 DB 구조 → SQL/ORM 참조 → 입력 범위 검사
  → FastAPI → Qwen 전체 분석
  → 요구사항의 DB 관련성에 따라 DB 호출 생략 또는 추가 분석
  → 응답 재검증 → 결과·실제 전달 facts 저장 + COMPLETED
  → Frontend job별 polling 및 결과 조회
```

Worker는 Backend 프로세스 안에서 실행한다. AI 서버는 Git/대상 DB에 직접 접속하지 않는다.
대상 DB의 업무 데이터 행을 모델로 보내거나 변경 SQL을 실행하지 않는다.
소스→DB 수집은 순차 처리이며 화면의 자동 상태 조회가 동시에 동작한다.
진행률 80%는 모델 대기 구간에도 나타나므로 시간 비율이나 남은 시간으로 해석하지 않는다.
화면은 서버 진행률을 임의로 높이지 않고 단계 활동·경과 시간으로 대기 중임을 보여준다. Backend Worker는 공개용 고정 문구의 단계 시작·완료 내역을 `analysis_jobs.analysis_options.activityLog`에 저장하고, 기존 작업 상태 API의 약 2.5초 조회로 최신 작업 내역을 보여준다. AI 응답 대기가 길어지면 Backend가 30초마다 대기 중임을 기록하고 현재 단계 경과 시간은 매초 갱신한다. 이 기록은 **Backend가 응답을 기다린다는 뜻이지 모델 계산 완료율을 증명하지 않는다.** 원본 서버 로그·접속 정보·예외 내용은 화면에 전달하지 않는다. **모델 내부 토큰 진행률이나 남은 시간 예측은 아직 제공하지 않는다.**
AI 서버는 내부 키로 보호된 `/api/analysis/project/stream`에서 일반 영향 분석과 필요 시 DB 영향 분석의 시작·완료 및 응답 형식 재시도를 안전한 코드로 순차 전달한다. Backend가 이 코드를 사용자용 문구로 바꿔 같은 작업 내역에 저장한다. 구버전 AI 서버가 스트림 경로를 제공하지 않으면 기존 최종 JSON 경로로 대체하며, 이때 AI 내부 단계 내역은 나타나지 않는다. AI 서버·Backend를 모두 재시작한 뒤 새 분석에서 확인해야 한다.
2026-10-14 로컬 재검증에서 AI 서버·Backend를 새 코드로 재시작했다. 실제 Qwen에 DB 저장 없는 최소 구조 분석을 스트림으로 요청하자 15·30·45·60초 heartbeat 후 약 66초에 `GENERAL_COMPLETED` → `DATABASE_SKIPPED` → 최종 결과가 도착했다. 최초 실행에서는 Python 3.9의 `asyncio.TimeoutError`를 처리하지 못해 15초에 연결이 끊겼으며, 이를 수정하고 회귀 테스트를 추가했다. AI 서버 테스트 44개가 통과했다. **이 시험은 AI 스트림 경로 검증이며, 새 작업을 만드는 Backend→Frontend→Supabase 전체 연동 검증은 아직 아니다.**
저장된 결과를 여는 `GET`은 모델을 다시 호출하지 않는다. 새 요구사항으로 분석을 시작할 때는 새 AI 판단이 필요하지만, 고정 Git SHA가 같고 현재 읽기 전용 DB 구조가 저장된 완전한 근거와 일치하면 Git 체크아웃·소스 재스캔을 생략한다. **DB 변경 여부 확인을 위한 구조 메타데이터 조회는 매번 수행**한다. 이전 소스/AI 입력/DB 수집이 잘렸거나 구조가 다르면 새로 수집하며, 재사용한 원본 작업 ID는 `analysis_jobs.analysis_options`에 남긴다.
요구사항 화면에서 **저장된 근거로 바로 분석**을 선택하면 완료된 작업의 소스·DB 근거를 기준으로 새 요구사항을 AI에 다시 분석시킨다. 이 방식은 사용자가 Git·DB에 변경이 없음을 확인해야 시작되며, **현재 Git·DB를 조회하지 않으므로 변경 여부를 자동 보증하지 않는다.** 후보는 수집 범위가 잘리지 않고 경고가 없는 완료 결과만 표시한다. 기본 선택인 **최신 Git·DB 확인**은 기존의 자동 비교 경로다.
분석 화면의 **이력으로 나가기**와 브라우저 뒤로가기·다른 화면 이동은 화면 조회만 중단하고 서버 작업은 유지한다. 진행 중에는 이동 확인을 보여준다. 새로고침·탭/창 닫기는 브라우저 기본 이탈 경고를 요청하지만 브라우저 설정에 따라 표시가 제한될 수 있으며, 종료 중 비동기 취소 요청은 보내지 않는다. **분석 작업 취소**는 `PENDING`/`RUNNING`을 `CANCELLED`로 변경하며 결과 저장을 막는다. 같은 Backend 인스턴스의 실행 스레드는 중단을 시도하지만, 여러 인스턴스나 원격 모델 계산이 즉시 멈춘다고 보장하지 않는다.
고착 작업을 실패 처리하는 로직이 있는 것과 lease/heartbeat·자동 재시도가 구현된 것은 다르다.

## 3. 현재 Backend API 범위

| 영역 | 구현 경로 |
|---|---|
| 사용자 | `GET /api/auth/me` |
| 조직 | `GET/POST /api/organizations`, `GET /api/organizations/{id}` |
| 조직 구성원 | 조직별 members 조회·추가·수정·삭제 |
| 프로젝트 | `GET/POST /api/projects`, `GET/PUT /api/projects/{id}` |
| Git 연결 | repository-connection의 시험·저장·조회 |
| DB 연결 | database-connection의 시험·저장 |
| 요구사항 | 프로젝트별 requirements 생성·목록, 접근 가능한 프로젝트 통합 `GET /api/requirements`, 단건 `GET /api/requirements/{id}` |
| 요구사항 버전·상태 | `POST /api/requirements/{id}/versions`, `PUT /api/requirements/{id}/status` |
| 분석 | `POST /api/projects/{id}/analysis-jobs` (선택적 `reuseFromJobId`·`confirmedUnchanged`), `GET /api/analysis-jobs/{id}`, `POST /api/analysis-jobs/{id}/cancel`, `GET /api/analysis-jobs?page=&size=&projectId=` 이력 |
| 결과 | `GET /api/analysis-jobs/{id}/result` |

현재 `/api/dashboard`, `/api/analyses`, `/api/models`, `/api/documents`, `/api/settings`에 대응하는 Controller는 없다. 분석 이력은 별도 `/api/analysis-jobs`에 구현했다.
아키텍처·영향도 전용 결과 API, 분석 승인/수정 API, 견적 API와 과거 요구사항 버전 목록 API도 확인하지 못했다.
DB `approved`, `corrected_result`, 견적·학습·배포 테이블은 존재하지만 관리 API/화면의 완료를 의미하지 않는다.
`001`~`008` migration 파일이 있으며 `008`은 신규 논리 삭제용이다. 과거 `001`~`007` 적용 여부는 사용자 기록에 따른다. `bootRun` 기동 검사에서 DB 스키마 검증은 통과했지만, 이번 작업에서 migration을 직접 실행하거나 기존 프로젝트 데이터를 수정하지 않았다.

## 4. Frontend에서 먼저 보완할 부분

전체 화면별 판정과 파일 근거는 [13번 Frontend 점검](13_2026-10-14_Frontend_구현_점검.md)을 기준으로 한다.

1. **프로젝트 목록·상세·수정:** 소스 종류·브랜치 표시와 논리 삭제·복구, 상세 이동, 기본정보와 Git·DB 연결 계정 수정 화면을 연결했다. 실제 계정으로 연결 시험→저장→재조회 및 권한을 검증하고, 기술 스택 `stack`의 실제 근거 매핑과 Git 주소 변경·연결 저장의 원자화를 후속 처리한다.
2. **이력·실결과 경로:** 이력 목록·특정 job 재열기는 구현했다. 새 API의 실제 계정·브라우저 검증을 하고, 전역 아키텍처·영향도 데모를 실제 저장 결과로 연결한다.
3. **요구사항 버전·상태·검토·승인:** 존재하는 API에 UI를 연결하고 없는 과거 버전 조회·분석 승인 API를 설계한다. 학습용 승인 정답 확보와 연결된다.
4. **오류·Mock 표시·미완성 버튼:** 없는 API·실행 미연결 버튼을 실제 기능처럼 표시하지 않고 빈 상태·실패·재시도·권한 거부를 처리한다.
5. **대시보드·조직·견적·고객 공개:** 각각 API/응답 정책과 UI를 기능 단위로 구현한다.
6. **모델·문서·설정 관리:** 운영 비밀의 서버 관리, 실제 학습/배포·업로드/RAG·권한을 갖춘 뒤 전환한다.
7. **검사·성능:** lint 오류, route lazy load, 실제 화면별 테스트를 추가한다.

학습 데이터 준비를 기다리는 동안에도 제품·Frontend 개발은 진행할 수 있다. 위 진행 화면 및 이력 재열기는 코드에 반영됐으므로 MacBook에서 중복 구현하지 말고 실제 연결을 검증한다.

## 5. AI와 MacBook 학습 상태

Mac Studio 기본 모델 선정과 운영 설정은 [10번](10_2026-10-14_AI_모델_선정_근거.md)·[11번](11_2026-10-14_MAC_STUDIO_QWEN_학습_평가_전달.md)을 참고한다.
대표 질문의 DB 단계는 팀/조직 확인을 요청했지만 전체 분석에는 근거가 약한 변경 제안이 남았다.
기존 기준 응답은 미승인 원본이며 학습 정답으로 바로 사용하지 않는다.
Mac Studio에서 요구사항 `REQ-001`의 Qwen 실제 전체 분석을 완료했다. 작업 `c48f6fdd-54db-4580-8455-b96efd4f0bdd`는 약 14분 22초의 AI 서버 요청 끝에 `COMPLETED`로 저장됐고, 테이블 26/26개·관계 81/81개가 모델 입력 범위에 포함됐다. 첫 DB 응답은 `DB_UNSUPPORTED_UNIQUE`로 거부됐으며 재시도 응답이 통과했다. 다만 일반 분석에는 기존 DTO와 DB 제약을 잘못 읽은 제안이 있어 **위험도 HIGH 85/100을 포함한 결과 전체가 사람 검토 전 상태**다. 사용자 확인으로 이 질문의 ‘팀’은 새 테이블이 아닌 **기존 `organization`**임이 확정됐다. 기존 프로젝트의 조직 미할당 행 처리와 ‘관리’ 권한 범위는 미확정이다. 다음 시험에는 이 해석을 요구사항 문구에 명시해야 한다.

이 성공은 **프롬프트 범용화·진행 화면 개선 이전**의 실행 결과다. 새 코드로 동일한 E2E를 완료했다고 기록하지 않는다. 이번 Mac Studio에서는 Git 임시 파일 소실 처리와 진단, 범용 프롬프트 및 JSON 응답 진단, 진행 화면 피드백을 커밋했다. 모델 교체·새 학습·승인 정답 생성은 하지 않았다.

후속 화면 확인에서 다른 요구사항 **‘멤버 비밀번호 초기화’** 작업 `296d29d2-b00c-4e79-bcda-d1029b09228d`가 2026-10-14 오후 5:52에 `COMPLETED`로 표시됐다(총 약 7분 54초, DB 판단 `NEEDS_CLARIFICATION`, 위험도 MEDIUM 55/100). 이 결과는 저장 화면에서 재조회할 수 있으나 **사람 승인 전**이다. ‘멤버 테이블’과 횟수의 의미를 묻는 방향은 적절했지만 존재하지 않는 `ProjectMember.java` 수정을 제안했으므로 자동 실행·학습 정답으로 사용하지 않는다. 실제 DB 변경은 하지 않았다.

MacBook은 M4 Max·64 GiB, Python 3.12.15·MLX 0.32.3·MLX-LM 0.32.0이다.
MLX Qwen 4bit의 짧은 추론과 마지막 4층·rank 4·2회 QLoRA 업데이트·어댑터 저장/재로딩을 검증했다.
실행 시험은 품질 학습이 아니다. 승인 데이터 변환·평가 도구는 구현됐지만 실제 승인 사례는 미확보다.
현재 분리 정책은 train/valid/test에 서로 다른 최소 3개 프로젝트 그룹을 요구하며 한 건도 검사 전용으로 받을 수 있다.
실제 긴 입력·업무 품질·Mac Studio 배포는 미검증이다.
상세는 [12번 학습 진행상황](12_2026-10-14_MacBook_학습_도구_진행상황.md)과 [데이터 안내](../training/DATA_WORKFLOW.md)에 있다.

### 추가 커밋 6개 병합 후 재점검

이전 MacBook 통합 검사는 `18c9a12` 기준이다. 이후 `6aa0b89`부터 `35f7a6a`까지 6개 커밋이 `011576f`로 병합됐다.
추가된 AI 단계 스트림, Backend 단계 이벤트 저장, 실시간 작업 내역 표시, Python 3.9의 대기 중 연결 종료 수정을 별도로 확인했다.
이 6개 커밋의 기능 소스는 원격과 같으며 프로젝트 관리 보완으로 덮어쓰지 않았다.

현재 통합 소스에서 Frontend 테스트 **40개**, 전체 lint와 production build(JS **573.43 kB**, gzip **168.96 kB**)가 통과했다.
AI 서버 pytest **44개**와 학습 도구 unittest **23개**도 통과했다. 빌드 크기 경고와 Python 라이브러리 경고 1개는 남아 있다.
브라우저 데모에서 프로젝트 상세→프로젝트별 이력→다른 프로젝트 선택→저장 결과 재열기를 확인하고,
추가된 작업 내역과 고객용 한 줄 요약이 함께 표시되는 것을 확인했다. 결과 재열기는 조회 경로이며 새 AI 작업 생성 경로와 구분한다.
Backend는 JDK 25가 필요하지만 이 맥에는 17·27만 확인돼 테스트를 재실행하지 않았다.
Mac Studio의 약 66초 Qwen 스트림 시험은 위 2절에 기록된 별도 장비의 검증이며 이번 MacBook에서 재현한 결과가 아니다.
실제 계정·DB·모델까지 연결한 전체 흐름과 실행 중 취소의 경쟁 상태는 계속 실환경 검증이 필요하다.

프롬프트 범용화에서는 특정 업무 용어 강제 검사와 UNIQUE·삭제 관련 키워드 거부, 명시적 DB 키워드에 대한 무관 분류 거부가 제거됐다.
한국어 문장·수집 테이블/컬럼·응답 구조 검증은 유지된다. 정답성 판단은 단위 테스트 통과와 구분해 기존 보류 평가 질문으로 다시 측정해야 한다.

Frontend 의존성은 `npm ci --ignore-scripts`로 설치했고, AI 서버는 별도 `.venv`에서 검사했다.
Backend의 과거 build/test·일회용 PostgreSQL 통합 시험 성공 기록은 [06번](06_2026-10-12_분석_Worker_구현_인수인계.md)에 보존한다.
과거 시험 숫자를 이번 환경의 통과 결과로 옮겨 적지 않는다.
빌드/단위 테스트 통과는 실제 API 기능·고객 공개 경계·모델 답변 정확도·승인 학습 데이터 확보와 별개다.

MacBook의 Frontend 작업은 Mac Studio 모델을 로컬 메모리에 올리지 않아도 시작할 수 있다. 다만 실제 분석 E2E는 Backend가 Mac Studio FastAPI에 접근할 수 있는 환경과 각 장비의 **서로 일치하는 내부 API 키**가 필요하다. 로컬 비밀값을 문서·커밋·화면 로그로 옮기지 않는다. 기능·테스트·문서 갱신은 목적별로 나누어 반영한다.

## 8. 2026-10-14 추가 질문·답변 이어 분석

- 분석 결과의 `databaseImpact.openQuestions`에 사용자가 답하거나 자유 형식 질문을 추가하면, 이전 결과를 수정하지 않고 **같은 요구사항의 새 버전**을 만든다. 새 버전의 `parent_version_id` 외래키는 이전 버전을 직접 가리키며, 질문 식별자는 모델 문장이 아닌 `분석 작업 ID + 질문 순번`이다. 이전 답변은 누적 보관한다. 질문 횟수의 고정 상한은 없지만, 한 번의 입력 크기는 제한하며 오래된 확인 내용은 AI 입력에서 제외될 수 있다. 제외 건수는 화면에 표시한다.
- Backend `POST /api/requirements/{requirementId}/follow-ups`는 완료된 분석이 현재 요구사항 버전과 같은 프로젝트에 속하는지, 사용자가 버전 편집 역할인지, 질문 번호가 원본 결과에 존재하는지 확인한다. Frontend 분석 결과 화면은 답변 저장 후 새 버전으로 재분석을 시작한다. 저장 성공·분석 시작 실패 시 동일 버전으로 재시도하도록 한다.
- **`supabase/migrations/009_requirement_follow_up.sql`은 2026-10-14 Supabase에 적용된 것을 읽기 전용 조회로 확인했다.** `parent_version_id` 컬럼·외래키가 존재하고, 당시 저장된 2개 버전에는 연결이 빠진 후속 버전이 없었다. Backend(8080)는 인증 없는 `/api/auth/me` 요청에 예상대로 401을 반환했고 AI 서버(8000)의 `/health`는 200이었다. 실제 계정으로 추가 질문 저장 → 새 버전 생성 → 재분석 → 이력 조회의 E2E 검증은 아직 하지 않았다.
- 이 기능의 단위 테스트·빌드 통과는 실제 Supabase migration, 권한별 UI, 긴 입력의 모델 품질을 검증한 것은 아니다. AI 질문·답변과 분석 결과는 사람이 검토하기 전까지 승인된 정답이 아니다.
