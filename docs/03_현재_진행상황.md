# 3. doenaai 현재 진행상황

기준일: 2026-10-14 · 검토 기준 소스: `adbd9c7` · 검토자: 김은태

**프로젝트 연결→근거 수집→AI 분석→결과 저장·조회 경로와 MacBook 학습 준비는 구현됐다.**
프런트 전체 화면과 검토·견적·고객 공개 업무가 완성된 제품은 아니다.
이번 점검은 현재 코드·API 계약과 자동 검사를 확인한 것이며 실제 계정·운영 DB·Mac Studio 연결을 다시 검증하지 않았다.
화면·API·DB 테이블 존재와 제품 기능 완료를 구분한다.

과거 8월의 “Worker·조직·요구사항 API 미구현” 기록은 현재 상태와 맞지 않아
[과거 기록](archive/03_2026-08-10_현재_진행상황.md)으로 분리했다.
9월·10월의 장비별 실연결 시험은 당시 검증으로 보존하며 현재 운영 상태를 보증하지 않는다.

이 표의 “구현”은 운영·보안·모델 정답성 인증이나 모든 브라우저 경로의 검증 완료를 뜻하지 않는다.
프로젝트 삭제 API는 없으며 상태 변경·수정과 구분한다.

## 2. 실제 구현된 분석 흐름

```text
프로젝트 등록: 조직 선택/생성 → 프로젝트 저장 → Git·DB 연결 시험/저장
변경 분석: Git 프로젝트 선택 → 요구사항·첫 버전 생성 → 현재 버전 ID 선택
공통: 분석 작업 PENDING → Worker 선점 RUNNING
  → 고정 Git commit 읽기 → 읽기 전용 DB 구조 → SQL/ORM 참조 → 입력 범위 검사
  → FastAPI → Qwen 전체 분석
  → 요구사항의 DB 관련성에 따라 DB 호출 생략 또는 추가 분석
  → 응답 재검증 → 결과·실제 전달 facts 저장 + COMPLETED
  → Frontend job별 polling 및 결과 조회
```

Worker는 Backend 프로세스 안에서 실행한다. AI 서버는 Git/대상 DB에 직접 접속하지 않는다.
대상 DB의 업무 데이터 행을 모델로 보내거나 변경 SQL을 실행하지 않는다.
소스→DB 수집은 순차 처리이며 화면의 자동 상태 조회가 동시에 동작한다.
진행률 80%는 모델 대기 구간에도 나타나므로 시간 비율이나 남은 시간으로 해석하지 않는다.
`CANCELLED`는 화면이 처리하는 종료 상태지만 이번 Controller 점검에서 취소 요청 API는 없다.
고착 작업을 실패 처리하는 로직이 있는 것과 lease/heartbeat·자동 재시도가 구현된 것은 다르다.

## 3. 현재 Backend API 범위

| 영역 | 구현 경로 |
|---|---|
| 사용자 | `GET /api/auth/me` |
| 조직 | `GET/POST /api/organizations`, `GET /api/organizations/{id}` |
| 조직 구성원 | 조직별 members 조회·추가·수정·삭제 |
| 프로젝트 | `GET/POST /api/projects`, `GET/PUT /api/projects/{id}` |
| Git 연결 | repository-connection의 시험·저장·조회 |
| DB 연결 | database-connection의 시험·저장 |
| 요구사항 | 프로젝트별 requirements 생성·목록, `GET /api/requirements/{id}` |
| 요구사항 버전·상태 | `POST /api/requirements/{id}/versions`, `PUT /api/requirements/{id}/status` |
| 분석 | `POST /api/projects/{id}/analysis-jobs`, `GET /api/analysis-jobs/{id}` |
| 결과 | `GET /api/analysis-jobs/{id}/result` |

현재 `/api/dashboard`, `/api/analyses`, `/api/models`, `/api/documents`, `/api/settings`에 대응하는 Controller는 없다.
아키텍처·영향도 전용 결과 API, 분석 승인/수정 API, 견적 API와 과거 요구사항 버전 목록 API도 확인하지 못했다.
DB `approved`, `corrected_result`, 견적·학습·배포 테이블은 존재하지만 관리 API/화면의 완료를 의미하지 않는다.
`001`~`007` migration 파일이 있으며 원격 적용은 과거 문서·사용자 확인 기록이다. 이번에 운영 DB를 조회하거나 migration을 실행하지 않았다.

## 4. Frontend에서 먼저 보완할 부분

전체 화면별 판정과 파일 근거는 [13번 Frontend 점검](13_2026-10-14_Frontend_구현_점검.md)을 기준으로 한다.

1. **프로젝트 목록·상세·수정:** `stack/source/branch`와 실제 `sourceType/repositoryUrl/defaultBranch` 계약을 맞추고 console 버튼을 실제 동작으로 연결한다.
2. **이력·실결과 경로:** Backend 목록 API와 특정 job 결과 재열기, 전역 아키텍처·영향도 데모 대신 실제 저장 결과를 연결한다.
3. **요구사항 버전·상태·검토·승인:** 존재하는 API에 UI를 연결하고 없는 과거 버전 조회·분석 승인 API를 설계한다. 학습용 승인 정답 확보와 연결된다.
4. **오류·Mock 표시·미완성 버튼:** 없는 API·실행 미연결 버튼을 실제 기능처럼 표시하지 않고 빈 상태·실패·재시도·권한 거부를 처리한다.
5. **대시보드·조직·견적·고객 공개:** 각각 API/응답 정책과 UI를 기능 단위로 구현한다.
6. **모델·문서·설정 관리:** 운영 비밀의 서버 관리, 실제 학습/배포·업로드/RAG·권한을 갖춘 뒤 전환한다.
7. **검사·성능:** lint 오류, route lazy load, 실제 화면별 테스트를 추가한다.

학습 데이터 준비를 기다리는 동안에도 제품·Frontend 개발은 진행할 수 있다.
이번에는 기능 코드를 수정하지 않고 현재 상태와 후속 작업을 정리했다.

## 5. AI와 MacBook 학습 상태

Mac Studio 기본 모델 선정과 운영 설정은 [10번](10_2026-10-14_AI_모델_선정_근거.md)·[11번](11_2026-10-14_MAC_STUDIO_QWEN_학습_평가_전달.md)을 참고한다.
대표 질문의 DB 단계는 팀/조직 확인을 요청했지만 전체 분석에는 근거가 약한 변경 제안이 남았다.
기존 기준 응답은 미승인 원본이며 학습 정답으로 바로 사용하지 않는다.

MacBook은 M4 Max·64 GiB, Python 3.12.15·MLX 0.32.3·MLX-LM 0.32.0이다.
MLX Qwen 4bit의 짧은 추론과 마지막 4층·rank 4·2회 QLoRA 업데이트·어댑터 저장/재로딩을 검증했다.
실행 시험은 품질 학습이 아니다. 승인 데이터 변환·평가 도구는 구현됐지만 실제 승인 사례는 미확보다.
현재 분리 정책은 train/valid/test에 서로 다른 최소 3개 프로젝트 그룹을 요구하며 한 건도 검사 전용으로 받을 수 있다.
실제 긴 입력·업무 품질·Mac Studio 배포는 미검증이다.
상세는 [12번 학습 진행상황](12_2026-10-14_MacBook_학습_도구_진행상황.md)과 [데이터 안내](../training/DATA_WORKFLOW.md)에 있다.

## 6. 이번 점검의 검증 결과와 한계

| 검사 | 2026-10-14 MacBook 결과 |
|---|---|
| Frontend Node 테스트 | 14개 통과. polling 11개·요구사항 payload 3개 |
| Frontend production build | 통과, JS 504.65 kB·gzip 151.52 kB, chunk 크기 경고 |
| Frontend lint | 실패. Prettier 오류 113개·미사용 router 경고 1개 |
| AI 서버 pytest | 38개 통과, 라이브러리 deprecation 경고 1개. 모델 호출은 Mock |
| 학습 데이터·평가 도구 테스트 | 22개 통과 |
| Backend Gradle 테스트 | 이번 점검에서 미실행. toolchain JDK 25 요구, 이 맥의 확인 가능한 JDK는 17·27 |
| 실제 브라우저·Supabase·DB·Mac Studio E2E | 이번 점검에서 미실행 |
| 문서 링크·변경 형식 검사 | 커밋 전 확인 |

Frontend 의존성은 `npm ci --ignore-scripts`로 설치했고, AI 서버는 별도 `.venv`에서 검사했다.
Backend의 과거 build/test·일회용 PostgreSQL 통합 시험 성공 기록은 [06번](06_2026-10-12_분석_Worker_구현_인수인계.md)에 보존한다.
과거 시험 숫자를 이번 환경의 통과 결과로 옮겨 적지 않는다.
빌드/단위 테스트 통과는 실제 API 기능·고객 공개 경계·모델 답변 정확도·승인 학습 데이터 확보와 별개다.

## 7. 완료 판단과 다음 작업

- 실제 API 호출·저장·재조회와 성공·빈 상태·오류·권한 거부를 확인한다.
- project/job/요구사항 버전을 선택·새로고침해도 결과가 올바르게 연결되는지 확인한다.
- 다른 조직·프로젝트의 접근 차단과 고객 응답 제한을 실제 계정으로 확인한다.
- 모델 판단과 승인 정답의 비교, 근거·위험한 제안·확인 질문의 사람 검토를 유지한다.
- 모델·데이터·접속 비밀·캐시는 Git에 올리지 않고 코드·문서·양식·검증 요약을 공유한다.
- 기능·테스트·문서 갱신은 목적별 커밋으로 나눈다. 이번 요청은 커밋까지만이며 푸시하지 않는다.
