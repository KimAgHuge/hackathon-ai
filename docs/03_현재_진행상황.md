현재 핵심 상태:

```text
1. 저장소 -> 기술 스택 탐지 -> sourceSummary
2. sourceSummary -> FastAPI -> Ollama -> 구조화 응답
```

두 기능은 각각 실제 환경에서 동작을 검증했다. 현재 남은 핵심 연결은
`analysis_jobs` 작업을 선점해 Git checkout, 기술 탐지, FastAPI/Ollama 호출과
결과 저장을 자동 수행하는 Worker다.

### 제품 정의와 현재 구현의 차이

목표 제품의 핵심 업무 흐름은 다음과 같다.

```text
고객 요구사항
  -> PM/PL 접수와 구체화
  -> 소스·DB 영향 및 위험 분석
  -> 작업 항목·예상 작업량·기간 산정
  -> PL/개발자 기술 검토
  -> PM 견적 작성
  -> 고객 제한 조회
```

현재 저장소는 이 흐름의 기반이 되는 인증, 프로젝트, Git/DB 연결과 분석 작업
생성까지 구현되어 있다. 반면 여러 회사의 데이터 격리, 고객 역할, 요구사항
버전, 견적과 작업 항목, 고객 공개 화면은 아직 구현되지 않았다. 따라서 현재
상태는 완성된 견적 제품이 아니라 기술 분석 플랫폼의 기반 단계다.

## 2. Git 기준 상태

2026-08-05 문서 정리 시작 기준:

```text
branch: main
HEAD: b56ba50
local origin/main: 89aee41
working tree: clean
local tracking 기준: ahead 2, behind 0
```

주요 최근 commit:

```text
b56ba50 Merge remote-tracking branch 'origin/main'
d0caebc Devstral 실제 통합 검증 결과 문서 반영
89aee41 프로젝트 문서를 세 문서로 통합
f6f710e 프로젝트 문서를 세 문서로 통합
cd95fb9 Mac Studio AI 작업 진행상황 인수인계 문서 추가
5e99ad5 AI 서버 Ollama 연동 및 범용 기술 스택 탐지 추가
```

실제 원격 조회는 이 Mac의 GitHub HTTPS credential이 없어 실패했다. 위
`origin/main`은 로컬 remote-tracking ref 기준이므로 commit/push 전 인증을
준비하고 다음을 다시 확인한다.

```bash
git status -sb
git log -5 --oneline
git fetch origin
```

사용자 요청 없이 commit 또는 push하지 않는다.

## 4. Supabase migration

현재 상태:

| Migration | 내용 | 상태 |
|---|---|---|
| `001_auth_rbac.sql` | profile/role/permission | 적용 |
| `002_projects_analysis.sql` | project/change/analysis | 적용 |
| `003_ai_model_training.sql` | model/training/evaluation/deployment | 적용 |
| `004_project_connection.sql` | source 유형과 DB 연결 | 적용 |
| `005_project_repository_connection.sql` | Git 인증 연결 | 적용 |
| `006_git_host_policy.sql` | Git host allowlist와 제약 | 적용 |
| `007_organization_requirement_estimate.sql` | 조직, 요구사항 버전, 견적과 검토 | PostgreSQL 16 검증 완료·Supabase 적용 필요 |

사용자가 Supabase SQL Editor에서 관련 테이블과 프로젝트별 저장 데이터를
정상적으로 조회했다.

기존 migration은 임의로 수정하거나 재실행하지 않는다. `007` 적용 전 SQL을
검토하고, 적용 후 조직 생성과 기존 프로젝트의 `organization_id` 배정이 필요하다.
Backend tenant/API 연결 다음에는 `008_analysis_pipeline.sql`에서 Worker claim,
lease, heartbeat, retry와 분석 이벤트를 설계한다.

`007` 로컬 검증 결과:

```text
PostgreSQL 16 migration 적용                       성공
조직 -> 요구사항 버전 -> 분석 -> 견적 -> 검토 저장  성공
다른 프로젝트의 요구사항 버전 연결                  거부
다른 프로젝트의 분석 결과 연결                      거부
요구사항별 current version 중복                     거부
DRAFT 견적의 고객 공개                              거부
다른 견적 작업 항목을 parent로 연결                  거부
신규 7개 테이블 RLS                                 활성화 확인
```

## 9. 테스트와 검증

### Mac AI Server

```text

```

검증 범위:

- FastAPI health
- 내부 API key 성공/실패
- 민감정보 차단
- camelCase 응답
- Ollama 장애/timeout

- 다중 생태계 모노레포

자동화 테스트에서는 Ollama 응답을 mock한다. 이후 기준 Mac Studio에서 실제
Devstral을 사용해 다음 통합 경로를 별도로 검증했다.

```text
Ollama 구조화 JSON 단독 추론             성공, 약 27초
FastAPI /api/models/health               HTTP 200
FastAPI /api/analysis/project            HTTP 200, 약 23.25초
API key 없는 분석 요청                   HTTP 401, Ollama 호출 없음
잘못된 Ollama URL                        HTTP 503
설치되지 않은 모델                       HTTP 503
0.001초 모델 timeout                     HTTP 504
```

응답은 Pydantic/JSON Schema와 camelCase 계약을 통과했고, 로그에 API key와
prompt 원문이 노출되지 않는 것도 확인했다.

### 다른 PC에서 테스트 재현

가상환경은 Git에 포함하지 않으므로 다른 PC에서는 새로 생성한다.

## 11. 알려진 문제와 제한

### Supabase JWKS timeout

관찰 오류:

```text
JwtException
GET .../auth/v1/.well-known/jwks.json
Read timed out
```

확인 내용:

- `issuer-uri`와 `jwk-set-uri` 형식은 정상
- Supabase 공식 상태는 정상
- DNS와 TCP 443 연결은 확인
- JWT 내용 오류가 아니라 Backend의 JWKS HTTPS 읽기 timeout

우선 확인:

```powershell
$jwksUrl = "https://{project-id}.supabase.co/auth/v1/.well-known/jwks.json"
curl.exe -v --connect-timeout 10 --max-time 20 $jwksUrl
```

브라우저/curl 모두 실패하면 VPN, proxy, firewall, 보안 프로그램 또는 네트워크
경로를 확인한다. curl은 성공하고 Spring만 실패하면 JVM proxy/TLS 환경을
확인한다. JWT 검증을 비활성화하는 방식으로 우회하지 않는다.

### 현재 분석 제한

- framework/언어 탐지는 구현됨
- class/method/API/SQL 관계는 미구현
- DB driver 탐지는 DB metadata 수집이 아님
- 모든 생태계 lockfile resolved version을 읽지는 않음
- 기술 catalog에 없는 dependency는 미분류로 보존
- sourceSummary와 LLM client가 Worker로 자동 연결되지 않음

### 현재 업무 도메인 제한

- 사용자와 프로젝트가 회사·조직 tenant로 분리되지 않음
- 현재 RBAC는 PM, PL, 고객, 개발자의 프로젝트별 권한 모델을 표현하지 않음
- `change_requests`만으로 고객 요구 원문, 정제본, 버전과 확인 상태를 관리하기 어려움
- 작업 항목, 작업량, 기간, 비용, 가정과 제외 범위를 저장할 견적 구조가 없음
- 고객에게 공개할 결과와 내부 기술 분석을 분리하는 정책/API가 없음
