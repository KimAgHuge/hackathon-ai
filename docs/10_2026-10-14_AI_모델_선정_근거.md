# AI 분석 기본 모델 선정: Qwen3.8 27B

기준일: 2026-10-14 · 결정: Mac Studio의 Ollama 분석 기본 모델로 `qwen3.8:27b`를 사용한다.

## 왜 Qwen을 선택했나

doenaai의 AI는 Git 소스와 읽기 전용으로 수집한 DB **구조 메타데이터**를 근거로 변경 영향과 위험을 제안한다. 이 업무에서는 빠른 답변보다 잘못된 DB 제약·데이터 삭제·근거 없는 변경안을 피하는 것이 중요하다. 같은 대표 질문을 비교했을 때, Qwen의 DB 전용 분석이 현재 후보 중 가장 안전한 판단을 했다. `팀`이 기존 `조직`과 같은 개념인지 확인해야 한다고 답했고, 기존 `projects.organization_id`가 nullable인 점과 기존 프로젝트 데이터 이관 위험을 언급했다. 요구사항에 없는 `UNIQUE` 제약도 제안하지 않았다.

**모델 출력은 검토용 제안이지 확정된 변경안이 아니다.** Qwen의 공통 분석은 일부 문장에서 팀을 조직으로 단정하고, 이미 조직 구성원을 조인하는 접근 로직에 변경을 권하는 등 근거가 약한 부분도 있었다. 사람의 검토와 AI 분석/추론 서버·Backend의 응답 검증을 유지한다.

## 비교 조건과 결과

대표 질문: “한 팀만 프로젝트를 관리 — 프로젝트 관리를 하나의 팀으로 제한한다. 이 변경에 필요한 소스 및 DB 변경 부분과 기존 프로젝트에 대한 위험을 알려줘.”

Mac Studio M1 Max·64GB에서 [프로젝트·조직·구성원 관련 migration](../supabase/migrations/007_organization_requirement_estimate.sql), [프로젝트 엔티티](../backend/src/main/java/com/doenaai/project/entity/Project.java), [접근 저장소](../backend/src/main/java/com/doenaai/project/repository/ProjectAccessRepository.java)의 구조를 발췌해 입력했다. `public.organizations`, `public.projects`, `public.organization_members`, `public.project_members` 네 테이블 및 관련 외래 키·인덱스를 제공했다. **실제 Supabase 행 데이터나 전체 저장소를 조회한 시험은 아니다.** 요구사항 일반 분석 → DB 관련성 판단 → DB 전용 분석이라는 [실제 AI 분석/추론 서버 경로](../ai-server/app/services/llm_service.py)와 같은 JSON 스키마·검증 로직을 사용했다. 호출당 제한은 300초, 검증 실패 시 재시도는 1회였다.

| 모델·조건 | 관찰된 시간 | 결과 |
|---|---:|---|

| `qwen3.8:27b`, 추론 끔, 이전 DB 전용 비교 | 약 68초 | 빨라졌지만 `UNIQUE` 관련 잘못된 제안이 다시 나타났다. |
| `qwen3.8:27b`, 추론 켬, 이전 전체 2단계 분석 | 약 5분 49초 | 최종 형식·검증 통과. DB 판단은 `NEEDS_CLARIFICATION`. 다만 공통 분석의 일부 변경 권고에는 근거가 부족했다. |

위 숫자는 **단일 대표 질문의 관찰값**이다. DB 전용 시험과 전체 2단계 시험, 추론 설정이 서로 다르므로 시간을 동일 조건의 속도 순위처럼 해석하지 않는다. Gemma·EXAONE의 DB 응답은 JSON 문법만의 문제가 아니라 [DB 일관성 검증](../ai-server/app/services/llm_service.py)에 걸린 내용상 오류였다. EXAONE이 DB에 접속하지 못한 것은 아니다. AI 모델은 DB에 직접 접속하지 않으며 Backend가 전달한 구조만 분석한다.

## DB 판단에서 특히 중요한 점

- 현재 `public.projects.organization_id` 외래 키는 프로젝트 한 행에 소유 조직 하나를 연결하지만, 여러 프로젝트가 같은 조직을 가질 수 있다. 여기에 `UNIQUE`를 추가하면 **조직당 프로젝트 하나**로 의미가 바뀐다. “프로젝트를 한 팀만 관리”라는 문구만으로는 정당화되지 않는다.
- `팀`이 기존 `public.organizations`와 같은 개념인지, 별도 업무 엔티티인지 확인해야 한다. 기존 조직이라면 현재 소유 관계가 어디까지 요구사항을 만족하는지와 NULL 프로젝트 처리 정책을 검토한다. 별도 팀이라면 연결 구조와 기존 데이터 이관 범위가 달라진다.
- 기존 `organization_id IS NULL` 프로젝트의 존재 여부는 이 시험에서 확인하지 않았다. 삭제·일괄 재할당을 확정안으로 제안해서는 안 된다.
- Qwen도 항상 맞는 것은 아니다. 실제 소스·DB 근거와 `promptCoverage`를 확인하고, 불명확하면 `NEEDS_CLARIFICATION`으로 사용자에게 질문해야 한다.

## 적용 상태와 운영 기준

- 로컬 [`ai-server/.env`](../ai-server/.env)의 `DOENAAI_AI_MODEL`, [설정 기본값](../ai-server/app/config.py), [환경변수 예시](../ai-server/.env.example)는 `qwen3.8:27b`로 맞춰져 있다. `.env`에는 비밀정보가 있으므로 Git에 올리지 않는다.
- 모델 교체 때문에 Backend·Frontend 코드를 바꾸지는 않았다. 실행 중인 AI 분석/추론 서버가 이전 환경변수를 읽은 상태라면 재시작 후 내부 모델 상태 API로 실제 모델을 확인해야 한다.
- 모델 선정 당시 테스트는 AI 분석/추론 서버의 분석 로직을 Ollama에 직접 연결한 재현 시험이었다. 이후 [실제 전체 분석 검토](evaluation/2026-10-14_qwen_실제_전체분석_검토.md)에서 Frontend → Backend → AI 분석/추론 서버 → Ollama → 결과 저장 경로를 한 차례 완료했다. 여러 프로젝트 크기와 반복 실행에서의 완주율은 아직 보증하지 않는다.
- Qwen은 정확도가 상대적으로 좋았지만 느리다. 실사용에서는 전체 소요 시간, 각 단계의 시간 초과·재시도, 잘못된 DB 변경 제안, 한국어 품질을 계속 기록한다. 제한 시간을 늘리기 전에 입력 범위와 누락된 근거도 함께 확인한다.
- Devstral·Gemma·EXAONE은 설치 상태를 유지하되 기본 분석 모델로 선택하지 않는다. Qwen 기본 설정과 검증 로직은 유지한다.

이 문서가 [2026-10-13 분석·학습 인수인계](08_2026-10-13_AI_분석과_맥북_학습_인수인계.md)와 [MacBook Codex 인수인계](09_2026-10-13_MacBook_Codex_인수인계.md)에 기록된 Devstral 중심의 **당시 모델 상태를 갱신**한다. 두 문서의 과거 테스트 기록과 아직 구현되지 않은 학습 작업 설명은 그대로 유효하다.
