# 시연 시나리오 (3분)

되나 AI의 시연 영상을 만들기 위한 문서다. 두 부분으로 되어 있다.

- **1부 실행 지침**: Claude 같은 에이전트가 맥북에서 웹 화면을 조작해 시연을 진행할 때 따르는 절차와 안전 규칙
- **2부 영상 제작 자료**: 시간표, 자막, 낭독 대본, 편집 방법 (자막 파일은 `시연_자막.srt`)

목표 영상 길이는 **3분(180초)**이다. 실제 제품 흐름 그대로 찍고, 오래 걸리는 대기 구간만 편집에서 빨리감기한다.

> 이 문서는 Git에 올라간다. 접속 정보, 비밀번호, 토큰은 이 문서에 적지 않는다. 비밀 값은 항상 사람이 화면에 직접 입력한다.

# 1부. 에이전트 실행 지침

## 1. 역할 분담

| 할 일 | 담당 |
|---|---|
| 화면 녹화 시작과 종료 | **사람** (맥은 `Cmd + Shift + 5` 또는 QuickTime) |
| 비밀번호, 토큰 입력 | **사람** |
| 화면 조작 (로그인 이후 이동, 입력, 클릭) | 에이전트 |
| 승인 버튼 클릭 | 에이전트가 사람에게 확인한 뒤 |
| 구간별 시작·종료 시각 기록 | 에이전트 |
| 영상 편집(배속, 자막, 음성) | **사람** (편집 프로그램) |

에이전트는 영상을 녹화하거나 편집할 수 없다. 화면을 조작하는 도구(브라우저 확장이나 컴퓨터 사용 기능)가 연결되어 있지 않다면, 조작은 하지 말고 각 단계에서 사람이 할 일을 안내하는 역할만 한다.

## 2. 시작 전 확인 (사람과 함께)

| 확인 | 내용 |
|---|---|
| 서버 실행 | 웹 화면, 서비스 서버, AI 분석 서버, 올라마가 모두 실행 중인지 |
| bge-m3 설치 | 맥에서 `ollama list`에 `bge-m3`가 보이는지. 없으면 `ollama pull bge-m3`를 실행하고 AI 서버를 재시작 |
| 시연 계정 | 승인 버튼이 보이는 권한의 담당자 계정으로 로그인되어 있는지 |
| 시연용 DB 계정 | **읽기 전용** 계정인지. 앱이 쓰는 쓰기 가능한 계정은 쓰지 않는다 |
| 프로젝트 이름 | 기존 프로젝트와 겹치지 않는 새 이름 (사람이 정한다) |
| 녹화 준비 | 사람이 녹화를 시작할 준비가 됐다고 말한 뒤에만 시작 |

## 3. 안전 규칙 (반드시 지킨다)

1. **비밀 값은 대화나 파일에 쓰지 않는다.** 비밀번호와 토큰 칸에서는 멈추고, 사람에게 "이 칸은 직접 입력해 주세요"라고 요청한다. 입력된 값을 읽거나 따라 적거나 캡처하지 않는다.
2. 접속 정보가 화면에 노출되면 즉시 멈추고 알린다. 영상 편집에서 가려야 한다.
3. **시나리오에 없는 버튼은 누르지 않는다.** 특히 아래는 금지한다.
   - 프로젝트나 요구사항의 삭제, 다른 프로젝트의 수정
   - AI 모델 관리 화면의 학습, 변환, 적용
   - 설정 변경, 사용자 권한 변경
   - 분석 중인 작업의 취소
4. **승인은 되돌릴 수 없다.** 화면에도 "검토 결정은 한 번만 저장할 수 있습니다"라고 나온다. 승인 버튼을 누르기 전에 반드시 사람에게 확인한다.
5. 같은 동작은 한 번만 다시 시도한다. 두 번째에도 실패하면 멈추고 실패 화면의 메시지를 그대로 보고한다.
6. 대기 구간에서는 화면을 닫거나 이동하지 않고, 30초마다 진행 상태만 확인한다.

## 4. 실행 절차

각 단계에서 **확인 기준**이 화면에 보이는지 확인하고 다음으로 넘어간다. 단계를 시작하고 끝낼 때마다 시각을 기록한다(5절).

### 단계 0. 오프닝

- 동작: 대시보드가 보이는 상태에서 시작한다.
- 확인 기준: 왼쪽 메뉴에 대시보드, 프로젝트 관리, 변경요청 관리, 분석 이력이 보인다.

### 단계 1. 프로젝트 신규 등록

- 동작
  1. 왼쪽 메뉴 **프로젝트 관리**에서 신규 등록 화면으로 이동한다.
  2. 프로젝트명을 입력한다(사람이 정한 이름).
  3. Git 저장소 URL에 `https://github.com/KimAgHuge/hackathon-ai.git`, 기본 브랜치에 `main`을 입력한다.
  4. 저장소가 비공개라면 인증 방식과 토큰이 필요하다. 이 값은 **사람이 직접 입력**한다.
  5. DB 종류, 호스트, 포트, DB 이름, 스키마, 읽기 전용 계정을 입력한다. 값은 사람에게 받아서 입력하고, **비밀번호 칸은 사람이 직접 입력**한다.
  6. **저장소 확인** 버튼을 누르고 성공을 기다린다.
  7. **연결 테스트** 버튼을 누르고 성공을 기다린다.
- 확인 기준: 저장소 확인과 연결 테스트가 모두 성공 상태이다. 둘 다 성공해야 **분석 시작** 버튼이 활성화된다.
- 실패 시: 실패 메시지를 그대로 보고하고 멈춘다. 접속 정보를 임의로 바꿔 시도하지 않는다.

### 단계 2. 프로젝트 구조 분석 시작

- 동작
  1. 화면 아래쪽 추론 설정을 확인한다(사람과 정한 강도: 낮음 또는 보통).
  2. **분석 시작** 버튼을 누른다. 프로젝트 저장과 구조 분석이 함께 시작되고 진행 화면으로 자동 이동한다.
  3. 진행 단계가 **완료**가 될 때까지 기다린다. 대기 구간은 영상에서 빨리감기한다.
- 확인 기준: 진행 화면이 열리고, 완료 상태에서 결과가 보인다.
- 이 단계가 먼저 끝나야 요구사항 분석에서 관련 근거만 골라 쓸 수 있다. 순서를 바꾸지 않는다.

### 단계 3. 요구사항 입력과 분석 시작

- 동작
  1. 왼쪽 메뉴 **변경요청 관리**로 이동한다.
  2. 요구사항 등록 폼에서 등록할 프로젝트(방금 만든 프로젝트)를 고르고, **제목**과 **요청 원문**을 입력한다(필수). 요구사항은 아래 "시연용 요구사항" 중 사람이 고른 것을 쓴다.
  3. **요구사항 저장**을 누른다.
  4. 목록에서 저장한 요구사항의 분석을 시작하는 버튼을 눌러 분석 옵션 패널을 연다.
  5. 옵션을 확인한다. 근거 수집은 **저장된 근거로 바로 분석**(구조 분석 직후라면 저장 근거가 있다)이거나 최신 확인 중 사람이 고른 것, 추론 설정은 사람과 정한 값, **AI에 보낼 근거**는 **관련 근거만 골라 보내기(RAG)**로 둔다.
  6. 패널의 **분석 시작**을 누른다.
- 확인 기준: "요구사항과 첫 번째 버전을 저장했습니다" 안내가 보이고, 분석 진행 화면으로 이동한다.

### 단계 4. 분석 진행

- 동작: 근거 수집 → AI 분석 → DB 검토 단계가 끝날 때까지 기다린다(영상에서 빨리감기).
- 확인 기준: 결과 화면이 열린다.
- 이 단계가 가장 오래 걸릴 수 있다. DB 검토가 길다.

### 단계 5. 분석 결과

- 동작: 결과 화면에서 쉬운 요약, 영향 영역, 위험도(변경 범위, 데이터, 보안, 구현 난도, 불확실성)가 보이게 둔다. 스크롤은 천천히 한다.
- 확인 기준: 요약과 위험도 구성이 화면에 보인다.

### 단계 6. 근거 확인

- 동작: 결과 항목 하나를 열어 파일명과 줄 번호, 관련 DB 테이블이 보이게 한다. 이 구간에 가장 오래 머문다.
- 확인 기준: 실제 파일 경로와 줄 번호가 화면에 보인다. **엉뚱한 파일이 근거로 나오면 단계를 멈추고 보고한다**(요구사항을 바꿔 다시 돌려야 한다).

### 단계 7. DB 영향 검토 결과

- 동작: DB 변경이 필요한지와 확인 질문이 보이게 한다.
- 확인 기준: DB 영향 상태와 확인 질문(있다면)이 보인다. DB와 무관하다고 나와 이 항목이 없으면 그대로 보고하고 넘어간다.

### 단계 8. 담당자 검토와 승인

- 동작
  1. 확인 질문이 있으면 사람이 알려 준 답을 입력한다. 답이 없으면 사람에게 묻는다.
  2. **사람에게 승인해도 되는지 확인한다.**
  3. 확인을 받으면 **분석 결과 승인**(또는 사람이 정한 경우 수정 후 **수정 결과 승인**)을 누른다.
- 확인 기준: 승인 완료 상태가 보인다.

### 단계 9. 분석 이력과 마무리

- 동작: 왼쪽 메뉴 **분석 이력**으로 이동해 방금 분석이 목록에 있는 것을 보여 준다.
- 확인 기준: 방금 분석이 이력 목록 맨 위에 보인다.

## 5. 시각 기록과 인계

에이전트는 저장소에 올라가지 않는 위치(예: 홈 디렉터리의 임시 폴더)에 로그 파일을 만들어 각 단계의 시작과 종료를 기록한다. 로그에는 비밀 값을 적지 않는다.

```text
HH:MM:SS 단계 N 시작
HH:MM:SS 단계 N 종료 (결과: 성공 또는 실패, 메모)
```

시연이 끝나면 에이전트는 사람에게 다음 표를 만들어 전달한다.

| 단계 | 실제 걸린 시간 | 영상 배정 시간 | 필요 배속 |
|---|---|---|---|
| 2 (구조 분석 대기) | | 약 20초 | 실제 시간 ÷ 20초 |
| 4 (분석 진행 대기) | | 약 15초 | 실제 시간 ÷ 15초 |

이 표가 있으면 사람이 편집에서 배속과 `×N배속` 자막의 N을 정할 수 있다.

## 6. 시연용 요구사항 후보

분석 대상이 되나 AI 프로젝트 자체이므로, 이 프로젝트에 대한 한글 한 줄로 입력한다. 소스 화면과 DB가 모두 관련되는 후보를 골랐다.

| 후보 | 요구사항 |
|---|---|
| 1 | 분석 결과를 승인한 담당자의 이름을 분석 이력 화면에 함께 보여주고 싶어요 |
| 2 | 반려된 분석 결과도 이력에서 따로 걸러서 볼 수 있게 하고 싶어요 |

어떤 후보를 쓸지는 사람이 정한다. 근거 파일이 엉뚱하게 나오면 문장을 조금 바꿔 다시 돌린다. 촬영 전에 한 번 리허설을 해서 결과를 확인한다.

## 7. 실패했을 때

| 상황 | 에이전트가 할 일 |
|---|---|
| 저장소 확인 또는 연결 테스트 실패 | 메시지를 보고하고 멈춘다. 접속 정보는 사람이 점검한다 |
| 분석이 실패 상태로 끝남 | 화면의 실패 메시지를 그대로 보고한다. 같은 요청을 한 번만 다시 시도한다 |
| 관련 근거 없음이 나옴 | 임베딩 모델(bge-m3) 설치와 AI 서버 재시작 여부를 사람에게 확인한다 |
| 근거 파일이 요구사항과 무관함 | 요구사항 문장을 바꿔 다시 돌릴지 사람에게 묻는다 |
| 접속 정보가 화면에 노출됨 | 즉시 멈추고 알린다 |

## 8. 한눈에 보는 시간표

| 구간 | 시간 | 길이 | 내용 | 영상 처리 |
|---|---|---|---|---|
| 0 | 00:00 ~ 00:05 | 5초 | 오프닝, 대시보드 | 실시간 |

| 2 | 00:30 ~ 00:55 | 25초 | 분석 시작과 구조 분석 | 대기 구간 빨리감기 |
| 3 | 00:55 ~ 01:15 | 20초 | 요구사항 입력과 분석 시작 | 실시간 |
| 4 | 01:15 ~ 01:30 | 15초 | 분석 진행 | 빨리감기 |
| 5 | 01:30 ~ 01:45 | 15초 | 분석 결과 | 실시간 |
| 6 | 01:45 ~ 02:10 | 25초 | 근거 확인 (가장 강조) | 실시간 |
| 7 | 02:10 ~ 02:25 | 15초 | DB 영향 검토 결과 | 실시간 |
| 8 | 02:25 ~ 02:50 | 25초 | 담당자 검토와 승인 | 실시간 |
| 9 | 02:50 ~ 03:00 | 10초 | 분석 이력, 마무리 | 실시간 |

실행 지침의 단계 번호와 영상 구간 번호는 같다. 자막 파일(`시연_자막.srt`)은 이 시간표를 기준으로 만들었다. 리허설에서 시간이 달라지면 편집 프로그램에서 자막 위치를 조정한다.

## 9. 구간별 자막과 대본

자막은 화면 아래쪽 가운데에 한 줄로 넣는다. 구간이 시작되면 번호 자막을 2~3초 보여주고, 이어서 보조 자막을 구간이 끝날 때까지 보여준다.

| 구간 | 자막 | 보조 자막 | 대본 |
|---|---|---|---|
| 0 | 되나 AI 시연 · 요구사항 한 줄에서 근거 있는 분석까지 | | 요구사항 한 줄이 근거 있는 분석 결과로 바뀌는 과정을 보여드리겠습니다. |
| 1 | 1. 프로젝트 등록 | 소스 저장소와 DB를 읽기 전용으로 연결 | 먼저 프로젝트를 등록합니다. 소스 저장소와 데이터베이스를 읽기 전용으로 연결해서, 원본은 건드리지 않습니다. |
| 2 | 2. 프로젝트 구조 분석 | ×N배속 · 분석 중 | 연결이 끝나면 프로젝트의 소스와 데이터베이스 구조를 분석해 자료를 만들어 둡니다. 시간이 걸리는 구간은 빨리감기했습니다. |

## 10. 낭독용 전체 대본

> 요구사항 한 줄이 근거 있는 분석 결과로 바뀌는 과정을 보여드리겠습니다.
>
> 먼저 프로젝트를 등록합니다. 소스 저장소와 데이터베이스를 읽기 전용으로 연결해서, 원본은 건드리지 않습니다.
>
> 연결이 끝나면 프로젝트의 소스와 데이터베이스 구조를 분석해 자료를 만들어 둡니다. 시간이 걸리는 구간은 빨리감기했습니다.
>
> 이제 고객의 요구사항을 그대로 입력합니다. 요구사항과 관련 있는 근거만 골라 AI에 보내도록 설정했습니다.
>
> 분석은 근거 수집, AI 분석, 데이터베이스 검토 순서로 진행됩니다.
>
> 결과는 쉬운 한 줄 요약과 영향 범위, 그리고 위험도로 먼저 보여줍니다.
>
> 여기서 항목을 누르면 실제 파일과 줄 번호, 관련 테이블이 나옵니다. AI의 말을 그대로 믿지 않고, 근거를 직접 확인할 수 있습니다.
>
> 데이터베이스를 바꿔야 하는지도 따로 검토해서, 확인이 필요한 질문까지 알려줍니다.
>
> 마지막으로 담당자가 확인 질문에 답하고 승인합니다. AI는 근거를 제공하고, 최종 판단은 사람이 합니다.
>
> 분석 결과와 근거는 이력에 남아 나중에 다시 확인할 수 있습니다.

## 11. 3분에 맞추는 방법

- 구간 2와 구간 4의 실제 대기 시간은 프로젝트 크기에 따라 다르다. 리허설에서 재서 아래 식으로 배속을 정한다.
  - 배속 = 실제 대기 시간 ÷ 영상에 배정한 시간
  - 예) 실제 6분 대기를 20초에 담으려면 약 18배속
- 입력 구간(구간 1, 3)은 타이핑이 길면 배속하되, 읽을 수 있는 속도는 유지한다.
- 3분을 넘기면 구간 7(DB 영향 검토)과 구간 9(이력)를 먼저 줄인다. 근거 확인(구간 6)과 담당자 검토(구간 8)는 줄이지 않는다.

## 12. 편집 지침

1. 자막은 한 번에 한 줄, 20자 안팎으로 쓰고 화면 아래쪽 가운데에 둔다.
2. 빨리감기 구간에는 `×N배속`을 화면에 표시한다. 시간을 줄였다는 것을 숨기지 않는다.
3. 진행 단계가 바뀌는 순간은 정상 속도로 남긴다.
4. 대기 구간은 완료 화면까지 이어서 찍는다. 결과가 나오는 순간은 자르지 않는다.
5. 구간별로 나눠 찍은 뒤 이어 붙인다. 신규 등록, 구조 분석, 요구사항 분석, 검토 순으로 나누면 편하다.
6. 접속 정보(비밀번호, 토큰)가 나오는 장면은 편집에서 가린다.

## 13. 영상에서 넣지 않는 것

| 항목 | 이유 |
|---|---|
| AI 모델 관리(학습, 변환) | 학습은 장비와 시간이 많이 들어 3분에 담기 어렵다. 슬라이드의 학습 서버 설명으로 대신한다 |
| 설정, 문서 관리, 아키텍처 화면 | 제출용 메뉴에서 제외된 화면이다 |
| 견적 화면 | 아직 구현되어 있지 않다 |
