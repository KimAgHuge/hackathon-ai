# 2026-10-21 빠른 시험 학습 인수인계

## 사용자 요청과 진행 범위

최근의 `변경요청에 목표 완료일 추가`를 최신 코드로 재분석하고, 새 결과를 검토한 뒤 학습 사례로 추가한다.
오늘은 동작 가능한 범위의 짧은 시험 학습이 우선이다. 운영 Qwen을 바로 바꾸거나 소량 자료로 품질 개선을 확정하지 않는다.
기존 승인 자료를 보존하며 미승인 결과와 도구 시험용 가상 답변을 승인 정답으로 만들지 않는다.

## 이 Mac Studio에서 확인한 상태

- AI 분석/추론 서버만 사용자 승인으로 재시작했다. 현재 실행은 최신 최종 정리 코드를 포함한다.
- 새 작업은 `42b126a7-33d6-417b-8815-ec815a519ba8`이다. 2026-10-21 14:08:42경 시작해 14:17:03경 완료했다.
  전체 처리 시간은 약 8분 21초이며, 일반 분석·DB 다섯 묶음·종합의 검증된 결과는 재사용하고 최종 정리만 다시 실행했다.
  화면 결과는 위험도 보통 43점이며, DB 판단은 추가 확인이 필요한 상태다. 재시도 없이 최종 구조 확인 검사를 통과했다.
- 검토 중 기존 DB 단계에 남은 인덱스 설명 오류를 확인했다. 수집된 컬럼 13개·인덱스 4개에 맞춰 수정 초안을 화면에 입력했다.
  실제 변경요청 기능과 저장 테이블의 연결은 미확인으로 남겼고, JSON 키가 없다는 이유만으로 전용 컬럼 추가를 필수로 단정하지 않았다.
  기존 행의 값을 채우는 작업과 스키마·배포 영향을 구분했다. 사용자가 15:14경 수정 결과와 검토 이유를 승인 저장했다.
  원본 분석은 보존되며 이 승인은 분석 검토이지 실제 DB 변경 승인이 아니다.
- 학습 초안의 일반 정답은 일반 입력의 테이블 개요·소스 근거로 답할 수 있는 내용으로 따로 수정했다.
  컬럼 13개·인덱스 4개 등의 상세 설명은 DB 정답에 유지하고 일반 정답에서 제거했다.
  현재 자동 초안이 이 구분을 완전히 대신하지는 않으므로 이후 사례도 단계별 입력·정답 일치를 직접 확인한다.
- 사용자가 정답·비식별화 확인과 전체 검사를 마친 뒤 15:28경 새 사례 한 건을 전송했다.
  게시 파일은 100,158바이트이고 로컬 NAS·outbox·전송 기록의 크기와 SHA-256이 일치한다.
  준비한 초안과 전송 파일도 두 확인 표시를 제외하면 같다. 실제 업무 학습은 아직 시작하지 않았다.
- 이전 완료 작업 `82bf35ad-f854-4272-b8c2-5268c29952b1`에는 설명 불일치가 있어 그대로 전송하지 않았다.
- 기존 승인 사례 두 건은 AI 학습 서버에서 수신·검증 완료이며, 현재 로컬 계약으로 다시 검사해도 통과했다.
- 마지막 서명된 `/api/training/intake` 조회는 `READY_FOR_DATASET`, 파일 2개·사례 2개를 반환했다.
  새 사례의 수신 알림은 접수됐지만 당시 상태는 `WAITING_FOR_FILE`이었다. 이후 사용자가 맥북의 파일 도착을 확인했다.
  맥북에서 수신·검증 완료와 실제 사례 수를 다시 확인한다. 파일 도착만으로 총 세 건 검증 완료를 확정하지 않는다.
- 수신 기능은 `FILE_LEVEL_EVIDENCE`, `DATABASE_SCOPE_REVIEW`, `DATABASE_CHANGE_SEMANTICS_V2`를 제공한다.
  새 `DATABASE_REVIEW_PLAN_V1` 제공은 확인되지 않았다. 필요한 사례는 검사 우회 없이 수신 서버 업데이트가 먼저다.
- 공유 NAS 역할의 iCloud Drive 폴더는 연결됐다. 기존 SSH 인증·호스트 검증을 유지한 연결은 실패했다.
  따라서 이쪽에서 맥북 학습 프로세스를 실행했다고 주장하지 않는다. 수신 API는 학습 시작 API가 아니다.

## 새 사례를 받기 전 확인

1. 웹 분석 완료를 확인한다. 최종 요약·위험도 이유·영향 영역·권장 사항이 상세 DB 판단과 맞는지 검토한다.
2. DB 구조 확인과 소스 연결·JSON 내부 값·실행 경로 미확인을 구분한다. 백필이 없다는 이유로 스키마 변경 위험을 지우지 않는다.
3. 검토 이유와 필요한 수정본을 저장하고, 학습 초안에서 정답·근거 일치 및 비식별화를 확인한다.
   두 확인란은 실제 확인 후에만 선택한다. 전송 전 검사와 수신·검증 완료까지 확인한다.
4. 최종 화면용 답변을 일반 단계 학습 정답에 무조건 복사하지 않는다. 일반 단계 입력에는 DB 테이블 개요만 있다.
   기존 `generalAnalysis`와 DB 단계 정답을 구분하고, 당시 입력으로 답할 수 없는 정답을 넣지 않는다.
   현재 파일·줄 검사는 원본 입력을 기준으로 하므로 변환된 일반 메시지에서 생략된 인용도 통과할 수 있다.
   실제 학습 메시지에 정답의 파일·줄 근거가 포함되는지 확인한다. 참조 수·글자 수 한도로 빠진 근거는
   검사 통과를 이유로 학습시키지 않으며 정답이나 입력을 검토한다. 이 범위 차이의 자동 차단은 아직 보완 대상이다.
5. 일반 정답의 선택 항목 `databaseReviewPlan`도 실제 스키마 포함 이름·파일 근거와 맞아야 한다.
   이름이 비슷하다는 이유로 대상 테이블을 만들어 넣거나 수신 기능 검사를 끄지 않는다.

## 맥북에서 바로 이어 할 작업

먼저 맥북 저장소의 현재 수정 사항과 학습 도구를 확인한다. 이쪽 저장소의 `training/train_lora.py`는 안내만 출력하는 파일이다.
맥북에 이미 만든 실행 도구가 있다면 덮어쓰지 말고 그대로 확인한다. 이 파일을 실행했다는 이유만으로 학습했다고 판단하지 않는다.
최신 코드의 커밋 목록은 `docs/03_현재_진행상황.md`를 확인한다. 커밋과 원격 푸시는 별개이므로
Mac Studio에서 푸시한 뒤 맥북이 같은 커밋을 받았는지 확인한다. NAS의 문서만으로 코드가 갱신된 것은 아니다.

1. 수신함 `training/datasets/incoming/`의 실제 검증 파일과 사례 수를 확인한다.
   새 자료까지 받았다면 기존 두 사례와 중복되지 않는지 확인한다. 파일·사례 ID·동일 입력의 중복은 합치기 전에 검사한다.
2. 운영과 같은 프롬프트·응답 계약·입력 변환을 적용한다. 주요 파일은 다음과 같다.

   - `training/dataset_contract.py`
   - `ai-server/app/models/analysis.py`
   - `ai-server/app/services/llm_service.py`
   - `ai-server/app/services/source_context.py`
   - `ai-server/app/services/database_scope.py`

3. 현재 이쪽 메시지 형식은 `messageFormatVersion=3`이다. 원래 일반·DB 두 단계 학습 정답 계약을 유지한다.
   최종 정리의 내부 `databaseFactsReview`는 그 두 정답에 추가하지 않는다.
4. 단일 프로젝트 안에서 서로 다른 원 요구사항으로 학습·검증·시험을 나누는 도구가 맥북에 적용됐는지 확인한다.
   이쪽 `export_dataset.py`는 아직 프로젝트 그룹 단위 분리다. 같은 프로젝트를 세 그룹으로 위장하지 않는다.
   같은 요구사항의 수정 버전·후속 질문은 모두 같은 분할에 두고, 시험 자료를 학습에 섞지 않는다.
5. `training/verify_qwen_compatibility.py`와 `training/QWEN_COMPATIBILITY.md`를 확인한다.
   기존 확인 모델은 `training/models/Qwen3.8-27B-4bit/`이며, 맥북에서 실제 존재·revision·로딩을 다시 확인한다.
6. MLX-LM 학습 실행 전 실제 토큰 수와 정답 구간이 길이 제한 안에 남는지 확인한다.
   실행을 성공시키려고 정답이나 핵심 근거를 잘라 버리지 않는다. 긴 자료가 들어가지 않으면 그 사례는 보관하고 가능한 승인 사례만 시험한다.
7. 첫 실행은 batch 1·소수 학습층·낮은 LoRA rank·약 10회 업데이트 정도의 짧은 시험으로 시작한다.
   실제 옵션은 설치된 `python -m mlx_lm.lora --help`와 기존 검증 도구로 확인한다. 메모리가 부족하면 중단하고 운영 모델은 유지한다.
8. 새 어댑터 경로에 저장하고 새 프로세스로 로딩되는지 확인한다. 기존 어댑터·기반 모델을 덮어쓰지 않는다.
   저장 성공과 학습 전후 정답 품질·처리 속도 개선은 별개다. 같은 평가 조건에서 비교하기 전 운영 Ollama로 전환하지 않는다.
