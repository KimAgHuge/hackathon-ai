# MacBook 학습 환경·데이터·평가 도구 진행상황

> 이 문서는 학습 영역의 진행상황이다. 전체 제품의 Frontend·Backend·검토·견적 미완료 항목은 [현재 진행상황](03_현재_진행상황.md), 화면별 후속 작업은 [13번](13_2026-10-14_Frontend_구현_점검.md)에 정리했다.

기준일: 2026-10-16 · 작성 장비: M4 Max MacBook · 작성자: 김은태

**Qwen 모델 실행과 짧은 QLoRA 호환성 검증, 승인 데이터 변환·평가 도구 구현까지 완료했다.**
실제 업무 정답 확보, 업무 학습, 학습 전후 품질 비교, Mac Studio 배포는 아직 진행하지 않았다.
이 문서는 `08`·`09`·`11`의 MacBook 학습 영역 placeholder·미검증 기록을 갱신한다.
Mac Studio 운영 설정과 기존 모델 비교 기록은 [11번 문서](11_2026-10-14_MAC_STUDIO_QWEN_학습_평가_전달.md)를 참고한다.

2026-10-14에는 자동 테스트 22개와 Python 문법 검사, 패키지 의존성 일관성 검사, `git diff --check`를 통과했다.
테스트는 승인 우회, 비밀정보 패턴, 분할 누출, 중복 입력, 없는 파일·DB 근거,
추가 JSON 필드, 누락된 응답, 불완전 thinking, 다른 평가 조건의 비교 거부를 포함한다.

새 평가 도구도 합성 UI 사례 한 건으로 실제 Qwen GPU 추론·원본 답변 저장·지표 생성을 확인했다.
약 19.95초, 입력 770토큰·생성 489토큰, 최대 MLX GPU 메모리 약 15.61 GiB였다.
답변이 JSON을 Markdown 코드 블록으로 감싸 반환해 JSON 형식 실패로 집계했다.
형식 오류를 자동 보정해 통과시키지 않았고, 이 응답을 학습 정답으로 채택하지 않았다.
이것은 도구 실행 경로의 시험이며 제품 정확도나 업무 품질 측정 결과가 아니다.

모델·데이터셋·어댑터·캐시·원본 평가 답변은 Git에 포함하지 않는다.
코드·패키지 버전·양식·검증 요약만 공유한다.

## 2026-10-16 AI 학습 서버 수신 준비와 재점검

최신 `da050e2`까지 확인하고 승인 초안·확정·전송 도구를 AI 학습 서버에서 점검했다.
이전 누락 항목인 `riskAssessment`는 사례 양식과 테스트에 반영돼 있다.
학습 도구 테스트는 이번 보완 후 **37개 통과**했다. 수동 복사 파일의 수신 권한과
잘못된 JSON 수신 확인에 대한 재시도·오류 원문 비노출 검사를 추가했다.
단위 테스트는 합성 사례와 모의 SSH 응답을 사용하며, 로컬 rsync와 CLI 수신도 확인한다.
이 결과를 실제 승인 데이터 확보나 장비 간 SSH 전송 성공으로 해석하지 않는다.

수신 도구는 처음 확정하거나 같은 파일을 다시 받을 때 파일 권한을 `600`으로 맞춘다.
수신 확인이 객체가 아니거나 건수가 정수가 아니면 성공으로 처리하지 않고 재시도한다.
로컬 `training/datasets/transfer-staging`과 `training/datasets/incoming`은 `700`으로 준비했다.
두 폴더는 Git에서 제외하며 실제 승인 데이터나 합성 학습 데이터를 넣지 않았다.

이 AI 학습 서버의 iCloud Drive `DoenaaiTrainingTransfer` 폴더는 확인됐지만,
점검 시 완성된 `*.jsonl`과 복사 중인 `*.uploading` 파일은 없었다.
폴더가 존재하는 것만으로 두 장비의 동기화나 전송 완료가 확인된 것은 아니다.
승인·비식별화된 파일을 받은 뒤 로컬 임시 폴더로 복사하고 `receive`를 실행해
발신 SHA-256·건수와 대조한다. 절차는 [데이터 전달 안내](../training/DATA_WORKFLOW.md)를 따른다.

같은 코드 기준으로 Frontend 테스트 **54개**, 전체 lint·빌드와 AI 분석/추론 서버 테스트 **47개**도
통과했다. JS 묶음 약 **600.51 kB** 경고와 Python 라이브러리 사용 중단 예정 경고 1개는 남는다.
Backend는 Java 25를 요구하지만 이 AI 학습 서버의 등록된 JDK는 17·27이므로 실행 검증하지 않았다.
실제 계정별 승인·초안 다운로드, 장비 간 수신, 긴 입력의 업무 학습·배포는 남아 있다.

## Mac Studio에서 다음으로 준비할 것

1. 검토 책임자와 승인 기준을 정하고 실제 요구사항·입력 근거를 검토한다.
2. 사례마다 소스 commit SHA, 요구사항 버전, DB 구조 수집 시각과 실제 전달 facts를 연결한다.
3. 전체 분석 및 필요한 DB 분석 정답을 각각 작성하고 승인·비식별 확인과 수정 이유를 기록한다.
4. 양식에 맞춘 JSONL을 전달한다. 최종 응답에서 사라진 DB 관련성 필드는 임의 추정하지 않는다.
5. 프로젝트 단위로 train·valid·test 배정을 준비한다. 현재 정책은 서로 다른 최소 3개 그룹을 요구한다.

기존 `docs/evaluation/qwen3.8_27b_team_management_baseline.json`은
`humanApproved=false`인 비교 원본이므로 학습·정답 평가 데이터로 바로 사용하지 않는다.
사례가 적어도 `--validate-only`로 전달 형식은 먼저 확인할 수 있다.

## MacBook에서 데이터 수신 후 진행할 것

1. 승인 사례 검사·JSONL 생성 후 시험 세트와 모델·프롬프트 버전을 고정한다.
2. 원본 MLX 모델로 학습 전 평가를 저장한다.
3. 실제 입력 길이에 맞춰 학습층·batch·rank·메모리를 확인하고 승인 데이터로 QLoRA를 수행한다.
4. 같은 입력과 생성 조건으로 학습 후 평가를 수행한다.
5. 라벨·형식·근거 지표 및 사람이 판단한 위험한 제안·설명·질문 품질을 비교한다.
6. 개선이 확인된 모델에 대해 Mac Studio/Ollama 배포 경로를 검증한다.

평가 도구는 승인 사례에 필요한 단계를 고정하고 재시도 없이 실행한다.
MLX에는 시스템 메시지로 JSON Schema를 전달하므로 Ollama의 `format` 제약과 같지 않다.
따라서 Mac Studio 운영 분기·재시도 포함 지연시간과 동일 조건 비교로 해석하지 않는다.
실행 명령과 지표의 한계는 [데이터·평가 안내](../training/DATA_WORKFLOW.md)를 기준으로 한다.
