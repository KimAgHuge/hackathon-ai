# Frontend 구현·API 연결 점검

최초 점검 기준: `35f7a6a` · 2026-10-15 최신 기능 코드 기준: `65cbe42`

**최신 인수인계는 [현재 진행상황 7·9절](03_현재_진행상황.md)을 먼저 읽는다.** 이 문서의 이전 점검 숫자와 화면 판정은 당시 시점 기록이며, 아래 표와 최신 보충 설명은 2026-10-15 코드 기준으로 갱신했다. 이번 다음 단계는 새 화면 개발보다 실제 계정·권한·긴 분석의 테스트다.

**화면이 존재하는 것과 실제 기능이 완성된 것은 다르다.** 프로젝트 등록과 현재 요구사항 분석 경로는 연결돼 있지만,
아키텍처·영향도 전용 실결과 화면, 모델·문서·설정과 견적 업무는 남아 있다.
최초 점검은 코드·API 계약 확인이었고, 이후 분석 진행 화면의 활동 피드백과 **분석 이력·결과 재열기**를 구현했다. 아래의 다른 미완성 기능까지 수정한 것은 아니다.
이력 목록과 근거 재사용·작업 취소·후속 질문 재시도·사람 검토의 모든 경계를 실제 Backend/Supabase로 끝까지 시험한 것은 아니다.

후속 반영: 프로젝트 목록의 행·이름에서 상세 화면으로 이동한다. 상세 화면은 기존 프로젝트 단건 API, Git 연결 조회, 새 DB 연결 메타데이터 조회, 최근 분석 이력을 조합한다. 목록·상세의 수정 버튼은 기본정보와 Git/DB 연결 계정을 변경하는 화면으로 이어진다. DB 비밀번호·Git 인증 토큰은 조회 응답/화면에 포함하지 않고 새 값만 입력받으며, 새 계정은 연결 시험 성공 후 저장한다. 새 DB 조회 API와 수정 흐름은 Backend 재시작 후 실제 계정·권한으로 확인해야 하며, 데모 브라우저 확인을 실 API E2E 완료로 보지 않는다.

## 확인된 계약 불일치·미동작

### 최신 프로젝트 화면에 기존 검증 기능 통합

원격의 프로젝트 상세·수정·연결 계정 화면, 이력 이동과 논리 삭제·복구를 유지하면서 이전 로컬 작업에서 빠진 부분을 보완했다.
목록은 실제 응답의 `description`, `sourceType`, `repositoryUrl`, `defaultBranch`를 기준으로 표시·검색한다.
근거가 없는 기술 스택 열을 설명 열로 바꾸고 검색에서 없는 값이 `undefined`로 일치하지 않도록 했다.

기본정보 수정은 조직·소스 방식을 원본에서 유지하며 이름·브랜치·저장소 길이와 상태를 검사한다.
저장 후 단건 조회로 다시 읽고, 기본정보와 연결정보 작업의 중복 요청을 막으며 실행 시 수정 권한도 확인한다.
화면 종료·프로젝트 변경 시 요청을 취소하고 이전 조회·시험·저장 응답은 무시한다.
다른 프로젝트를 열 때 이전 연결 대상과 입력한 토큰·비밀번호를 초기화한다.
미저장 변경사항은 화면 이동과 새로고침 전에 확인하며 저장 중 화면 이동을 막는다.
요청 취소는 화면 갱신을 중단하는 장치로, 서버에서 이미 수행한 저장을 되돌리는 기능은 아니다.

데모 목록·단건·생성·수정·삭제·복구는 같은 브라우저 저장소를 공유한다.
기본정보와 삭제 표식은 새로고침 뒤에도 유지하며 접속 비밀은 해당 저장소에 넣지 않는다.
연결 테스트·저장은 모의 응답이며 실제 접속이나 인증정보 보관 검증으로 해석하지 않는다.
이 구분을 목록·상세·수정 화면에 표시했다.

Git 주소·브랜치를 바꾸면 기존 연결과 잠시 불일치할 수 있으므로 기본정보 저장 후 새 인증정보로 연결을 다시 시험·저장해야 한다.
서비스 로그인 계정 변경은 이 화면의 범위가 아니다.

### 실제 Backend에 없는 화면 API

| Frontend 호출 | 실제 Backend 점검 결과 |
|---|---|
| `/api/dashboard` | 대응 Controller 없음. 대시보드는 기존 `/api/projects`, `/api/requirements`, `/api/analysis-jobs`를 사용 |
| `/api/analyses` | 데모 경로만 남음. 실제 이력 화면은 새 `GET /api/analysis-jobs`를 사용 |
| `/api/models`, `/api/documents` | 대응 Controller 없음 |
| `/api/settings` 및 AI 분석/추론 서버·AI 학습 서버·Supabase 연결 시험·저장 | 대응 Controller 없음 |
| `/api/projects/demo/architecture`, `/api/projects/demo/impact` | 대응 결과 API 없음 |
| `/api/projects/demo/analysis`, `/api/analysis-jobs/demo` | 기존 데모 래퍼. 실제 UUID 기반 분석 경로에 사용하지 않음 |

`VITE_USE_MOCK=false`는 Mock 대신 API를 호출하게 할 뿐 위 API를 만들지 않는다.
이력·모델·문서 목록은 API 실패를 사용자에게 안내하는 흐름도 추가 점검이 필요하다. 대시보드는 전체·부분 실패를 안내한다.
Architecture/Impact store는 오류를 기록하지만 화면에서 이를 설명·복구하는 UI를 확인하지 못했다.

### 버튼·안내가 실제 기능을 보증하지 않는다

- AI 모델 `배포`는 console 출력만 하고, `학습 시작`·`배포 상태 확인`·`상세`는 실행 연결이 없다.
- `문서 업로드`는 클릭 핸들러나 파일 업로드 경로가 없다.
- 설정 Mock 응답은 실제 서버 설정을 바꾸지 않는다. 설정 화면의 내부 API 키·Supabase service-role 입력은 실제 운영 설정 방식과 별도로 재설계해야 한다. 서버 비밀값은 Backend 로컬 설정에서 관리한다.
- `StepHeader`의 “병렬 분석”·구조/영향도 단계는 목표/데모 표현이다. 실제 Worker는 Git→DB→관계→AI 순서이며, 데모 결과 화면으로 이어지는 완성된 실분석 wizard가 아니다.
- DDL 업로드, Tibero/MySQL/MariaDB/MSSQL, 공급자 App 연동은 현재 비활성·준비 중이다.

## 이미 구현된 기능을 다시 미구현으로 적지 않는다

실제 변경요청 화면은 `LiveRequirementAnalysis.vue`와 `requirementApi.js`를 사용한다.
현재 버전 생성·선택적 분석은 가능하고, Backend에는 별도 버전 생성·상태 변경 API도 존재한다.
다만 이 두 API의 Frontend 편집·상태 UI가 없다. 과거 버전 목록을 반환하는 API도 이번 Controller 점검에서 확인하지 못했다.
`AnalysisProgressView.vue`는 단순 한 번 조회가 아니라 polling·DB 판단·수집 근거·범위 경고를 표시한다.
기존 `/architecture`·`/impact` 데모와 실제 job 결과 화면은 서로 다른 경로다.

### 후속 반영: 분석 중인 화면의 동적 피드백

Mac Studio에서 [`AnalysisProgressView.vue`](../frontend/src/views/AnalysisProgressView.vue)에 **실제 job 필드**를 이용한 활동 문구, 현재 수집/AI 단계 강조, 경과 시간, 마지막 조회 시각을 추가했다. 단계·문구 판정은 [`analysisProgress.js`](../frontend/src/lib/analysisProgress.js)로 분리하고 [`analysisProgress.test.js`](../frontend/tests/analysisProgress.test.js)로 검사한다. 기존 [`analysisPolling.js`](../frontend/src/lib/analysisPolling.js)의 약 2.5초 상태 조회는 유지하며, 스타일 변경은 [`main.css`](../frontend/src/assets/styles/main.css)에 있다. 접근성의 reduced-motion 설정도 반영했다.

이는 기다리는 동안 화면이 멈춘 것처럼 보이지 않도록 하는 **UI 피드백**이다. Backend가 제공하지 않는 모델 내부 단계·토큰 진행률은 추정하지 않고, 서버의 80%를 임의로 올리거나 완료 예상 시간을 만들어내지 않는다. MacBook에서는 이 기능을 새로 만드는 대신 실제 브라우저에서 긴 분석 중 표시·실패·재조회·새로고침 동작을 검증하면 된다.

후속 변경으로 Backend Worker의 안전한 단계 시작·완료 문구를 `analysis_jobs.analysis_options.activityLog`에 저장하고, 기존 상태 조회 응답에 포함해 **실시간 작업 내역**에 최신순으로 표시한다. AI 응답 대기 중에는 해당 단계 경과 시간이 매초 갱신되고, Backend가 30초마다 응답 대기 내역을 추가한다. 이는 모델의 내부 처리율을 뜻하지 않는다. 원본 애플리케이션/Ollama 로그, 인증정보, 예외 원문은 브라우저에 보내지 않는다. 모델 내부의 실제 완료율은 알 수 없으므로 80%를 시간에 맞춰 증가시키지 않는다. Backend 재시작 후 새 분석에서 확인할 수 있으며, 과거 작업에는 내역이 없을 수 있다.
AI 분석/추론 서버의 `POST /api/analysis/project/stream`도 일반 분석·DB 분석 시작/완료와 검증 재시도 코드를 전달하며, Backend가 허용된 코드만 사용자용 작업 내역으로 저장한다. 기존 JSON API는 유지하고 구버전 AI 분석/추론 서버의 스트림 404는 기존 경로로 대체한다. 따라서 AI 단계 내역까지 보려면 **AI 분석/추론 서버와 Backend를 둘 다 재시작하고 새 분석을 실행**해야 한다.

후속 로컬 변경에서는 [`AnalysisHistoryView.vue`](../frontend/src/views/AnalysisHistoryView.vue)와 [`appApi.js`](../frontend/src/api/appApi.js)를 실제 작업 목록 API에 연결했다. 행을 열면 기존 job ID의 저장 결과/상태 화면으로 이동하며 **새 AI 작업을 만들지 않는다**. 요구사항 작성 화면에서 프로젝트별 이력으로 바로 이동할 수 있다. 이력의 ‘근거 재사용’ 표시는 새 분석에서 같은 Git SHA·동일한 완전 DB 구조를 확인한 뒤 소스 스캔 근거를 재사용했는지 나타낸다. DB 메타데이터는 변경 검증을 위해 다시 읽고 새 요구사항의 AI 호출은 다시 수행한다.

요구사항의 **새 분석**에서는 두 경로 중 하나를 선택한다. 기본값은 최신 Git·DB 확인 후 가능한 근거를 자동 재사용한다. **저장된 근거로 바로 분석**은 완료·비절단·무경고 결과에서 선택하며, 사용자가 Git·DB 변경 없음에 동의한 뒤 현재 연결 조회 없이 새 요구사항으로 AI를 다시 호출한다. 따라서 소스·DB가 실제로 바뀌었다면 오래된 근거로 잘못 판단할 수 있다. 진행 화면을 떠나는 것은 서버 작업을 유지하고, 별도 취소 버튼은 대기/실행 작업을 취소한다. 브라우저 뒤로가기·다른 화면 이동은 이탈 확인을 보여주며, 새로고침·탭/창 닫기는 브라우저 기본 경고를 요청한다. 브라우저 종료로 서버 작업이 자동 취소되지는 않는다. 두 경로 모두 Backend 재시작과 실제 계정·DB 검증이 필요하다.

## 이번 인수인계의 다음 순서 — 테스트 우선

1. **로그인·권한:** 실제 계정의 프로필 조회 일시 실패와 401/403, 세션 만료·계정 전환에서 보호 화면과 이전 권한 노출 여부를 시험한다.
2. **프로젝트·이력:** 상세/연결 수정/논리 삭제·복구, 프로젝트별 분석 이력·결과 재열기를 실제 계정·여러 프로젝트·빈 상태로 확인한다.
3. **후속 분석:** 답변 저장→새 버전→재분석, 취소·실패 뒤 원 질문 복귀·같은 답 재시도, 저장 답변 복원, 단계 내역 최근 10건과 접힌 이전 내역을 확인한다.
4. **사람 검토:** AI 원본 승인·수정본 승인·반려, 권한 거부·중복 결정 거부, 새로고침 뒤 검토 이력 표시를 시험한다. 내용이 틀린 AI 원본은 정답으로 승인하지 않는다.
5. **반응형·표현:** 긴 질문·수정 JSON의 공통 입력창, 좁은 화면·키보드 조작·밝음/어두움 테마, 위험도 점수·등급·구성요소 일관성을 시험한다.

실제 오류가 확인되기 전에는 새 기능 개발을 시작하지 않는다. 이후 개발 후보인 아키텍처/영향도 실결과 화면, 과거 요구사항 버전, 견적·고객 공개, 모델·문서·설정 관리와 번들 분리는 [현재 진행상황](03_현재_진행상황.md)의 미완료 범위로 남긴다.

새로고침 후 복원과 데모 자료 미혼입을 확인한 상태를 뜻한다.

MacBook에서 작업을 시작할 때에는 [현재 진행상황](03_현재_진행상황.md)도 함께 확인하고, `git status -sb`·`git log -1 --oneline`으로 최신 코드가 반영됐는지 확인한다. Frontend는 모델 파일 없이 개발할 수 있지만 실제 분석 E2E에는 Mac Studio FastAPI 연결이 필요하다. UI에서 실제 Backend에 아직 없는 API를 호출하는 화면은 Mock/준비 중 상태를 명확히 구분한다.
