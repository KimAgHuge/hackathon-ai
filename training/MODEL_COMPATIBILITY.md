# 사용 모델과 학습 모델의 자동 연결

웹의 학습 작업을 조회하면 백엔드는 AI 분석 서버가 현재 선택한 모델을 확인한 뒤
`GET /api/training/capabilities?model=모델식별자`로 학습 서버를 조회한다.
모델 이름을 포함한 전체 요청 경로를 기존 공유 키로 서명한다.
학습 서버는 등록된 로컬 MLX 모델·다운로드 고정 버전·지원 학습기를 대조하고
대응하는 모델의 승인 자료만 반환한다. 현재 사용 모델은 화면에서 임의로 지정하지 않는다.

학습 시작도 현재 사용 모델을 다시 확인한다. 화면에서 확인한 모델 또는 로컬 기반 모델의
버전·경로·학습기 대응이 바뀌면 기존 요청을 거부한다. 미등록 모델을 Qwen으로 대체하지 않는다.
진행 중인 작업은 접수 당시 기반 모델을 유지한다. 다른 모델의 상태를 조회해도 실행 중인
작업의 전역 모델 경로를 변경하지 않는다. 모델 다운로드·패키지 설치·학습 시작은 자동 실행하지 않는다.

## 맥북 설정

기존 Qwen만 사용하는 경우 `DOENAAI_TRAINING_MODEL_DIR`을 그대로 사용할 수 있다.
이 경로는 `qwen3.8:27b` 전용이며 다른 모델 이름에는 적용하지 않는다.

여러 모델의 대응 정보를 관리하려면 `model-registry.example.json`을 로컬 설정 파일로
복사하고 실제 로컬 모델 경로를 입력한다. `training/.env`에서 다음 값을 설정한다.

```dotenv
DOENAAI_TRAINING_MODELS_FILE=/absolute/path/to/local-model-registry.json
```

등록 항목은 분석 모델의 정확한 식별자를 키로 사용하며 다음 세 값만 받는다.

| 항목 | 의미 |
| --- | --- |
| `directory` | 맥북에 이미 준비된 MLX 모델 폴더의 절대 경로 |
| `baseModel` | 해당 폴더의 `download_manifest.json`에 기록된 `modelId` |
| `trainer` | 서버에 구현된 학습기 식별자 |

로컬 파일 경로는 브라우저로 전달하지 않는다. `revision`은 다운로드 명세에 고정된
40자리 버전이어야 한다. 브라우저가 파일 경로나 실행 명령을 전달할 수 없다.
같은 모델을 두 설정에 모두 쓰면 등록 파일의 명시적 대응이 우선한다. 설정 파일 오류가
발생하면 기존 Qwen 경로로 조용히 대체하지 않는다. 초기 환경변수 변경 뒤 수신 서버를
재시작한다. 등록 파일의 이후 변경은 다음 조회에 반영되며 기존 화면의 시작 식별값은 무효가 된다.
실제 로컬 설정 파일과 모델 가중치는 Git에 넣지 않는다.

## 현재 지원 범위

실행 가능한 학습기는 `qwen-mlp-trial-v1`이다. 기존에 검증한
`qwen3.8:27b` → `mlx-community/Qwen3.8-27B-4bit`의 Qwen 마지막 MLP 시험 학습에만 사용한다.
학습 서버에 MLX·MLX-LM·Transformers가 설치돼 있고 모델 설정·가중치가 준비돼야 한다.
모델 파일의 이름을 바꾸거나 다른 모델에 이 학습기 이름을 붙여 지원 범위를 넓힐 수 없다.

Gemma·EXAONE·Devstral 등은 MLX 기반 모델을 등록하더라도 해당 구조의 학습기를
구현하고 실제 로딩·짧은 학습·저장·재로딩을 검증하기 전까지 실행하지 않는다.
다른 학습기는 `TRAINER_UNSUPPORTED`, 대응 모델이 없으면 `MODEL_NOT_REGISTERED`로 안내한다.
라이브러리에서 모델을 불러올 수 있다는 것과 현재 Qwen 전용 학습기로 학습할 수 있다는 것은 별개다.

## 반영과 확인

백엔드와 맥북 수신 서버에 같은 최신 코드를 반영하고 재시작한다.
웹의 사용 모델 변경을 완료한 뒤 학습 작업 탭을 열거나 새로고침하면 현재 모델에 맞는 대응을 조회한다.
학습 서버가 이전 코드이면 모델별 조회 경로가 지원되지 않으므로 학습 실행을 허용하지 않는다.
모델 변경 중인 화면의 예전 시작 요청, 미등록 모델, 지원되지 않는 학습기, 잘못된 다운로드 명세,
다른 생성 모델의 자료가 학습에 섞이지 않는지는 자동 검사로 확인한다.
실제 GPU 학습과 맥북 원격 반영은 별도로 확인해야 한다.

## 2026-10-21 맥북 반영 확인

`DOENAAI_TRAINING_MODELS_FILE`이 `.env` 허용 목록에서 빠진 문제를 수정했다.
따옴표·공백·`export`·주석, 기존 환경변수 우선순위와
`.env → 수신 서버 시작 → 학습 작업 저장소` 전달을 회귀 검사했다. 학습 도구 141개가 통과했다.
Qwen은 기존 `DOENAAI_TRAINING_MODEL_DIR`로 정상 대응하므로 별도 로컬 등록 파일을 만들지 않았다.

18:18경 IntelliJ 터미널에서 활성 학습이 없는 것을 확인하고 수신 서버를 정상 종료·재시작했다.
이 맥북의 `8011` 포트에 서명한 읽기 요청으로 다음을 확인했다. 백엔드에서 이 맥북으로
접속하는 경로를 다시 시험하거나 실제 학습을 시작한 것은 아니다.

| 확인 항목 | 결과 |
| --- | --- |
| Qwen 모델별 기능 조회 | HTTP 200, `trainingExecution=true`, `trainingReasonCode=READY` |
| Qwen 기반 모델 | `mlx-community/Qwen3.8-27B-4bit`, revision `10c35caafbb80f7dc6a7a432cdd11af10a6d4818` |
| 미등록 `devstral:latest` 조회 | HTTP 200, `trainingExecution=false`, `MODEL_NOT_REGISTERED`, 대응 대상 없음 |
| 수신함 | 파일 3개·사례 3건 보존 |
| Qwen 학습에 선택된 자료 | 0건, 생성 모델 기록이 없는 기존 자료 3건 제외 |
| 진행 중 학습 | 0건 |
| 보존 검사 | 수신 원본·기존 어댑터의 파일 9개 크기·SHA-256 유지 |

`READY`는 모델과 학습 환경의 준비 상태다. 승인 자료가 충분하거나 학습이 완료됐다는 뜻이 아니다.
기존 3건은 `sourceModel`을 임의로 추가하지 않고 보존한다. 다음 자료는 최신 분석 서버가
실제로 생성 모델을 기록한 분석을 검토·승인해 전송해야 한다. 웹 시험 학습에는 서로 다른
원 요구사항 3그룹과 길이 상한 안의 학습·검증 자료가 필요하다.

현재 추론 모델 선택은 동적이며 Qwen은 최초 기본값이다. 학습 실행은 Qwen 전용 학습기와
확인한 구조로 제한한다. Devstral을 고정해서 실행하는 조건은 없고, 다른 모델의 학습을
허용하려면 해당 구조의 학습·저장·재로딩 경로를 구현하고 검증해야 한다.
